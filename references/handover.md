# 交付与独立使用

交付按 GEO 顾问的项目目的与场景组织，使客户或接手者能理解结果、执行下一步，并在包含建站时安装、编辑、检查与维护网站。所有交付状态以实际文件和操作证据为准。

## 场景交付与完成边界

| 场景 | 必要交付 | 完成依据 |
|---|---|---|
| 新建官网 | 项目简报、内容资料包、栏目与全站设计方案、独立前后台及数据库、SEO／GEO 与内置监测实现、安装使用维护说明、验收与观察记录；包含上线时另交正式环境及维护交接 | 按约定阶段检查方案、代码或实际运行；运行阶段需安装、访问、编辑保存并回读，正式上线另验真实地址和环境 |
| 旧站诊断与局部改造 | 现状诊断与问题清单、优先级和逐页改造方案、阶段结论与下一步；进入实施时另交局部改造成品、备份回退及复查维护交接 | 问题、证据、建议与目标页面对应；已诊断、已实施、已复查和待处理分列，修改须验证实际生效及关联功能 |
| 多站信息一致性梳理 | 站点清单与主体关系、共用事实表、合理差异与冲突、逐站修改建议、梳理结论及交接；包含修改时逐站补实际改动与复查材料 | 每项事实有主体、来源和适用站点，每条动作能定位页面；梳理、修改与 AI 识别状态分别记录 |

顾问的项目简报可并入方案或诊断，写清客户问题、受众、访客行动、权限、阶段和排除项。下方完整项目清单按实际场景适用，不为仅诊断或多站信息一致性梳理制作空代码、空库或虚构部署地址。服务器选用理由、费用与维护责任按 deployment.md 交接；持续代运营和无限期运维另定范围。

各场景按上表交付；完整新站再按下方项目清单逐项核对，旧站和多站的详细步骤见 workflow.md。执行时结合 acceptance.md 确认实际检查范围。可以合并文档和表格，不按清单行数机械创建文件；每项交付注明实际文件或证据位置、完成阶段、未完成原因和下一步。资料与方案完成、文件生成、运行通过、正式上线及平台效果观察分别报告。顾问与企业未提供验收标准时，根据已约定的目的与功能整理建议，并明确业务确认、验收和维护分工。

## 使用说明分别写什么

Skill 目录的 README 面向顾问，简要说明目的、三类场景与交付、快速开始、推荐输入、主要功能、使用条件与验收；完整资料清单和技术步骤链接到对应参考文件。具体项目的运行版本、账号入口和实测结果写入该项目的使用说明，不把某台电脑的环境当成所有使用者的配置。

### 网站项目 README 与维护说明

下列内容用于生成网站的安装和维护交接，按实际实现和交付阶段填写；详细技术项可放在维护说明并从项目 README 链接。旧站仅交本次诊断或改造所需说明，多站梳理交逐站材料，不强制套用新站安装清单。

1. 适用范围、输入资料、输出、真实或教学数据状态、预览隔离及业务限制；教学说明写在交接材料，不自动进入访客页面。
2. 需要 Skill 辅助维护时说明加载和调用方法：在支持本地 Skill 的工具中加载完整目录，确认其发现 SKILL.md；平台具体入口按实际版本填写，不声称所有 Agent 自动兼容。企业日常维护直接使用网站后台。
3. 项目环境：已测系统、PHP/MySQL 版本及扩展，网站与内置模块依赖；涉及 Agent 执行时记录实际 Agent 与模型，选用外部系统时再单列其依赖。未运行阶段只写目标条件及未验证范围。
4. 从空目录和空库安装启动的实际命令、工作目录、配置位置、管理员初始化方式、成功现象。网站项目 README 明确写出实际前台/后台入口、首次初始化账号 `admin`、默认密码 `123456`、网站设置 → 账号设置的修改入口，以及重启不会覆盖已修改密码。默认凭据与数据库、邮箱凭据区分；实际新密码与私有服务凭据单独交接，不写入公开文档。
5. 面向运营的简明后台说明：登录、修改企业信息、新增内容、按名称选分类及关联、换图、查看、保存和删除。使用实际页面上的中文名称；初始化、来源内部记录、目录导出、缓存与故障命令另列维护说明，不要求运营先理解数据结构。
6. 内置监测的安装接线、当前目录、身份口径、代理配置、日志导入、事件/请求区别、预览隔离、清单更新与数据清理；MySQL ew_ 表、config/monitor.json 和私有快照随站备份。明确选用 GEOInflow 时，再交付原项目获取与版本核对步骤、来源记录位置、部署或复用路径、同一提交的官方安装入口、环境预检、首次登录与健康检查、本站标识与入口、目录导入、日志接收及处理、统计口径、异常处理与后续复查；监测 PostgreSQL、私有配置与密钥独立备份，记录升级恢复方法。
7. 域名、主机、监测资源、存储备份及可选模型费用，已用资源与新增支出分开；未选择时填待定。
8. 数据库、媒体、配置与源码的备份恢复，更新前读回和回滚方法。
9. 数据库连接、路由、上传、权限、会话、HTTPS、发布后缓存未更新、CDN 清理失败、索引规则错误、资源加载慢与监测无数据的排查位置及负责人。
10. 维护人、适用版本、已完成及未完成事项；凭据通过安全方式单独交接。
11. 资料判断、参考来源与设计取舍、主题方案与样式文件位置、素材使用范围；说明哪些是后台可改内容，哪些属于全站设计变更。
12. 选定的页面缓存、TTL、排除规则、命中判据、失效范围和重试/停用方法；说明保存、删除、恢复和换图后的普通匿名回读步骤，源站与 CDN 的实际生效范围和延迟。
13. 标题摘要、canonical、robots、索引指令、sitemap、JSON-LD 和重定向的生成/配置位置；预览切换正式域名及数据状态的发布步骤。
14. 组件清单、资源预算、PHP OPcache/数据库索引、性能测量工具与复现条件；实验室实测、真实访问第 75 百分位及未观察项分别列出。
15. 自查范围及执行入口、页面与功能清单、实际覆盖数量、问题修复与复查结果、本阶段通过/未通过依据和未检查项；这些合并进既有项目验收材料，不要求独立验证文件，也不以规则完整冒充实际已通过。

本地运行、演示部署、正式上线、监测入口配置及真实数据接入分别描述。只有正式域名实际验收后才能称正式上线。

## 实施交接与演示

按项目实际人员明确业务确认、设计开发、验收和后续维护责任，可由同一人承担多项职责。业务负责人核对企业事实与公开范围，技术负责人完成实现、检查和运行交接；开展独立试用时，由未参与制作的使用者按说明操作并反馈问题。Agent 不代填真人操作或认可。

实施记录写明任务范围、输入位置、负责人、预期结果、验收方法、依赖、目标日期、实际状态及证据，可合并进项目交接说明。根据本次约定安排方案审阅、代表页评审、实现、试用、复查和交付；日期到达不自动授权测试或证明任务完成。环境、资料或监测条件缺失时，列具体问题、负责人和下一步，继续不依赖该条件的工作。

安装由承担环境维护的人按技术说明完成；企业日常操作只读面向运营的简明说明。独立试用时，由未参与制作的非技术使用者按中文菜单和字段完成新增内容、换图、保存、修改联系方式及查看监测，不需理解来源 ID、JSON 或缓存术语；制作人代操作、解释字段和额外指导逐项记录。没有真人试用条件时，Agent 自查与独立使用结论分开，不代填结果。

维护验收要回读实际结果：保存一项业务条件或联系方式后，匿名检查受影响的详情、列表、首页共用位置及关联输出；技术验收再核对适用的 JSON-LD、缓存、目录与 sitemap，普通运营无需手改这些输出。涉及资质、数字或案例时，核对相应证据和适用范围同步。问题由发现者复查，技术负责人核对完整流程；换资料和有无 Skill 对照按 acceptance.md 的一致条件执行。

交接或中断时，在同一份私有项目记录中写清最后完成的阶段、产物位置及版本、待办、阻塞与下一步。接手者按 workflow.md 的中断续做要求核对实际状态后继续，无需重跑已经完成且仍有效的工作；未执行的验收仍保留未执行。

需要演示时，按实际交付说明客户问题、所选场景、主要页面或改造结果、后台维护和监测证据，最后交代未完成项与下一步；时长由使用者确定。旧站和多站只展示实际完成的诊断、改动或梳理结果。使用教学数据时在介绍或交接材料中说明，不默认把说明写入官网公共模板；用户明确要求课堂标识时单独配置。

监测尚未接入时，说明接入条件和未完成项，不制作假数据演示。验收标准以约定范围及本 Skill 的适用检查项为准；交付到指定位置，向他人发送文件须有相应授权。

最终压缩包只含需交付的正式文件及必要依赖说明，移除凭据、会话、未获准分发的私有材料、缓存和无关临时文件；用户明确要求的企业输入资料可独立放入资料目录并说明用途，保留原件，不混入运行数据。正式文件使用稳定名称和净稿，不夹入编辑批注、版本对比或操作聊天记录。

Skill 包必须包含 assets/monitor 与集成、测试说明，不包含真实密钥、日志或数据库；不默认包含可选 GEOInflow 整库或运行依赖。部署项目保留固定提交的获取/复现步骤；需离线交付原项目时单独提供源码或镜像及对应版本依据，保留原许可与必要第三方声明，说明尚需联网取得的依赖。来源和部署状态用于复现与维护，不能当作已运行的证据。

## 运行交付状态核对

完整新站读取项目 private/delivery-status.json；旧站和多站使用本场景交接记录。按实际范围分别报告官网可用性、前后台验收、内置模块接入、当前目录、请求/事件回读、规则更新与维护、浏览器实测；选用外部系统时单列其状态。对未完成项列出真实原因、已完成准备与继续所需动作。不得用官网检查数量概括监测完成情况；未执行系统安装、构建、健康检查或导入时不得提供虚构入口、账号或接入成功结论。
