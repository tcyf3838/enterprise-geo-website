# 原生 PHP 前后台生成规范

每次建站，根据企业页面方案与内容模型生成独立网站。通用部分固定功能和行为要求，栏目、字段、表结构、模板及代码由 Agent 在项目中实现。

## 共用后端

~~~text
H5 前台 ── PHP 服务器渲染 ─┐
                          ├─ 共用业务服务 / PDO ─ MySQL
H5 后台 ── 登录后编辑 ─────┘

官网后台访问监测 ── 内置报表与权限
应用请求 / 浏览器事件 / 导入日志 ── 官网 MySQL ew_ 表
~~~

所有官网内容读写通过同一业务层。前台只读公开内容，后台按权限读写。不得为前后台建立两套重复的企业资料表并依靠人工同步。

首页主视觉、推荐卡片和共用页头中的企业、产品及服务事实也读取当前内容与来源许可，不把型号、参数或业务承诺写死在模板中。修改或删除对应内容后，这些位置同步更新或隐藏，避免正文已改而首页仍展示旧事实。

默认复制 Skill 的 assets/monitor 到项目，并按 native-monitor.md 完成适配器、迁移、路由、脚本、后台报表与维护接线。内置模块复用官网数据库与管理员权限，不依赖外部实例；原版 GEOInflow 仅按明确需求另行接入。

## 项目结构约定

建议将以下职责分开；具体文件名由项目确定并写入 README：

| 目录职责 | 内容 |
|---|---|
| public/ | 唯一 Web 根目录，前台、后台入口及静态资源 |
| app/ | 数据访问、权限、内容服务、模板与共用逻辑 |
| config/ | 私有配置与不含真实凭据的示例 |
| database/ | MySQL 建表、初始化和需要时的迁移文件 |
| storage/ | 媒体、会话及其他私有运行文件 |
| tools/ | 管理员初始化、导入预览/应用、导出及目录工具 |
| private/ | 来源底稿、内容映射、输入包和私有执行记录 |
| docs/ | 安装、后台使用、监测、维护和验收说明 |

只有 public 映射到 Web。配置、数据库文件、工具和来源原件不对外开放。项目运行时不引用 Skill 的本地路径。

## 后台布局与导航

后台面向非技术企业人员。实际启用的业务内容与素材栏目提供查找、新增、编辑、删除；新增和编辑使用同一张紧凑表单，保存后直接更新网站。只有一个公开地址的企业介绍等单页直接进入编辑，不提供重复新增入口；服务端也限制重复创建，不把多个记录映射到同一地址。企业设置以编辑保存为主，概览与监测以查看筛选为主，咨询记录按查看和处理需要设计，不机械添加无意义的增删按钮。无需经过草稿、发布、下架、重新发布等内容流程；只有用户明确要求审批、多版本或定时发布时才另行设计。

桌面采用左侧紧凑纵向导航与右侧工作区，手机采用可展开菜单。一级按目的划分工作台、内容管理、素材管理、网站设置、访问监测；只有多个相关入口时才设二级。侧栏一次展开当前所属分组，选中态、缩进和底色清楚；刷新和直接进入编辑页不展开全部分组。长菜单可滚动，手机触控区域至少 44px，Escape、遮罩和焦点管理可用；无脚本仍能到达主要入口。

侧栏文字使用清楚的列表尺度：桌面导航正文通常 14—16px，分组文字不大于主要入口；行高、缩进与间距表达层级，不使用前台大标题字号或巨型留白。初始只展开当前分组；点击组标题仅切换目标组，采用单组展开时收起其他组，点击叶子链接不触发所有组展开。不能给不同组绑定同一布尔状态或通配打开全部折叠项。当前项、刷新、直接访问和浏览器返回分别检查。

最近编辑使用实际更新时间排序，精度至少到秒，并为同时间记录提供稳定次序；不能只存日期导致同一天的多次编辑次序失真。首发时间保持不变，页面显示与 Schema 日期使用同一事实并按各自格式输出。

工作台只保留常用操作、实际内容数量及最近编辑，不放草稿与上下架统计、花哨图表和开发指标。内容依据、公开目录、缓存、初始化、日志和技术命令保留在私有维护工具，不设成运营必须学习的栏目。

列表统一为“标题与新增按钮 → 查找与必要分类筛选 → 列表 → 分页”。默认列为名称/标题、必要分类、更新时间、操作，图片有识别价值时显示小缩略图。每行直接提供醒目的编辑、删除按钮；查看网站是次要入口。不要添加无业务必要的状态筛选、批量工具、审批流或装饰性指标。关键词、分类和有效页码在保存与返回后保留，手机不横拖即可找到操作。网站设置的二级入口同样显示当前选中态。图片列表将上传放在标题附近，默认显示缩略图、说明、使用中或未使用状态与操作；编辑字段和实际引用位置按需展开，支持搜索清除和分页。

## 按钮规范

|操作|可见按钮文字|统一颜色含义|
|---|---|---|
|查询|查找、筛选|蓝色实心背景，清晰对比文字|
|创建|新增、上传|绿色实心背景，清晰对比文字|
|修改|编辑、更换|橙色实心背景，清晰对比文字|
|删除|删除|红色实心背景，清晰对比文字|
|提交|保存|蓝色实心背景，作为表单主要动作|
|辅助|取消、返回、查看、关闭|灰色或浅底按钮，仍有明确边界|

这些是后台操作语义，不随前台主题改成一套单色。具体色值保证文字对比，颜色加文字共同表达用途；不能只用图标、悬停才出现的控件或无底色小链接作为主要动作。列表、表单、素材与监测筛选保持一致。桌面按钮通常 34—38px 高，手机不小于 44px；禁用、悬停及键盘焦点清楚，删除不挨着保存造成误点。

## 紧凑表单

一项内容在同一编辑面板内完成，不把每组字段拆成相距很远的大卡片。桌面合理使用两列：短字段同排，正文保持主要宽度，封面与产品要点可置于相邻窄列；小屏按阅读顺序单列。容器宽度以实际工作区为准，不强迫用户左右寻找必填信息。

- 字段间距通常 10—14px，分组间距 16—20px，面板内边距 16—20px；这些是起点，须实际查看。避免反复大标题、过高说明区、过大的图片预览和一项一个容器。
- 名称、分类、简介、正文和封面集中；产品按资料提供必要参数，文章提供署名，FAQ 默认只显示问题与回答，回答使用直接输入的多行文本框，不套用每段类型、排序、删除等块编辑工具；有明确结构化编辑需求时再提供。FAQ 不强制图片与重复简介。
- 短字段用单行输入，简介默认 2—3 行，正文按内容提供合理高度，不用多个空白巨型文本框撑长页面。必要的段落或列表编辑保留简单控件；不默认拖拽装修器、步骤向导或复杂多窗口。
- 相关内容、搜索展示等低频项合并到就近的“更多设置”，默认收起；常用字段和保存按钮始终容易找到。不把必填项藏起来。共用企业身份和联系方式优先展示，较少调整的首页标题、简介与主图归入“首页展示”；短文案输入不使用六行以上的空白框。咨询详情优先展示需求、处理状态与简短备注，邮件通知信息默认折叠，通知失败时展开具体原因。
- 图片使用小缩略图、名称与“选择/更换”按钮，支持在当前页面查找、上传并选用，正文不丢失。选图后立即更新缩略图，默认适配素材；有实际需要才出现裁切控制。允许在内容表单选择新封面，随内容一起保存并自动选用，不能要求先另开素材页、保存正文、再重新进入编辑。新上传需校验并确认使用许可；保存失败清理临时文件，提示重新选择文件，保留其他输入与版本。未保存预览也使用当前新图，必要时允许仅用于图片显示的本地 blob 预览。
- 主要动作只有“保存”，另设“取消/返回”；预览确有价值时作为次要入口，不成为必须经过的一步。保存后直接回到原列表，提示“已保存，网站页面已更新”。不要求再点发布或确认公开复选框。
- 长表单可使用紧凑吸底操作栏，小屏和短屏不遮挡最后字段；不要把五六个工作流动作挤成多行。

## 资料校验与保存行为

简化操作不能删除登录鉴权、CSRF、参数校验、事实使用边界、输出转义、上传校验和版本冲突保护。内部 ID、slug、source_ids、confirmed、public_allowed、demo、JSON-LD 与缓存配置不交给运营填写。

经授权的企业人员点击保存，即对本次输入的自有业务信息负责；系统可内部记录操作者、时间、内容和依据范围。仍不能以普通保存擅自将教学样例、证明材料冲突或不允许公开的素材转成已核验事实。正式站遇到具体缺口时在当前表单就近说明并保留输入；预览站仍保持访问与索引隔离。

- 保存执行服务端校验，再在事务内写入，并同步前台、目录与缓存；不需要普通保存确认弹窗。新建校验失败仍为新建，不制造空记录。
- 失败保留本次文本输入、已登记的图片选择、关联与原始版本；复选框和多选关联以本次提交为准，字段缺席表示未勾选或空集合，不能回退到旧值把用户取消的选项重新选上；浏览器无法恢复的本地文件选择明确提示重新选择，不假称已保留待上传文件。并发冲突不自动推进版本强行覆盖；用普通中文说明合并方式，技术详情只入私有日志。
- 表单离开、退出、切换图片等可能丢失输入时才提醒；取消后保留输入与会话。已保存或未修改时不误报。空文件选择控件按空值比较，不将浏览器临时生成的文件时间戳视为编辑；选择和取消上传后均验证离开提示。
- 预览若保留，使用本次未保存输入和相同安全渲染，不写业务表、不污染公开缓存；关闭返回原字段。无需运营理解数据结构。
- 关联按标题选择，不能填写 ID；已删除内容自动从选择器、前台链接和公开目录排除。字段必须真正影响前台，不能交付无作用的装饰字段。

## 删除与素材管理

删除是明确业务动作，不能仅把原有“下架”按钮改名而保留整套发布流程。内容删除后从当前列表、详情、推荐、关联、导航、公开目录和 sitemap 消失。优先以内部软删除、审计和备份防误删；不要求运营理解删除状态或先进入另一套审批。历史未公开记录迁移时保持不公开，不能因界面简化而自动全部公开。

删除先显示对象名称和影响并确认，默认可取消。GET 只读取或展示确认，实际删除使用有权限、CSRF、版本检查的 POST。重复提交、过期编辑、并发引用和失败重试不能误删或让内容重新出现。删除记录的底层保留不等于继续对匿名访客提供正文。

素材也以查找、新增、编辑、删除组织。上传支持真实文件类型、大小与像素校验，保存在私有持久目录，经受控媒体路由访问；原始素材与后续上传用同一规则。编辑支持名称、图注、alt、替换和必要的内部备注。图片网格默认只展示缩略图、名称及操作，编辑时才展开紧凑字段。

删除素材前重新计算共用图片与所有未删除内容的引用，在同一事务锁或等效机制内保护引用；正在使用的图片列出实际使用位置并阻止删除。不能只靠禁用按钮。图片删除使用真实删除：确认后删除该网站媒体库中的原文件、缩略图/尺寸变体、登记在该素材名下的替换旧文件及数据库记录。默认没有回收站、恢复入口或“文件仍保留”的提示。不能仅标记 deleted_at、隐藏列表或改名移到另一目录冒充删除。用户指定的外部原始材料目录不属于网站媒体删除范围。

文件删除前解析并核对全部目标在本站媒体目录内，检查同文件的其他素材引用；不按扩展名或模糊通配符扩大删除范围。失败时如实提示并允许重试，不把部分删除报成成功；审计可保留操作时间与对象名称，不额外复制图片或设置隐蔽回收站。页面内选图、上传和替换与素材页复用同一后端校验。上传成功即能选用，失败、取消和会话过期保留正文；处理焦点、Escape、手机内部滚动、过期响应及防重复提交。替换后刷新全部真实引用和资源版本。

## 需要生成的后台功能

|功能|实现要求|
|---|---|
|管理员|登录、退出、修改密码、失败限制、闲置超时；无公开初始化入口；初始 admin / 123456，后台可修改密码|
|企业信息|共用名称、简介、图片和联系方式一处保存、全站生效|
|实际业务栏目|查找、新增、编辑、删除；统一保存，真实持久化|
|素材|查找、上传、编辑/更换、删除；引用保护、确认后的实际文件与记录删除|
|编辑表单|按类型精简、单一紧凑面板、主要保存动作清楚、失败保留输入|
|事实和许可|内部追溯与实际校验，缺口就近说明，不设复杂运营流程|
|时间与网址|首次有效保存确定首发时间，后续修改保留；稳定 URL，迁移单独处理|
|访问监测|沿用管理员权限，清楚筛选、分页与导出，不制造虚假指标|
|持久保存|同一 MySQL 数据源、事务、参数化 SQL、版本与审计；刷新重启仍保持|

后台必须对每个实际启用的内容栏目，用隔离内容完成新增、查找、编辑、保存、取消删除及确认删除，再以匿名普通请求回读。产品、服务、问答和文章按本项目栏目方案选用，不为验收添加未约定的栏目；约定应有但尚未实现的功能记录为未完成。企业设置、概览及监测按各自实际操作验收，不能只交静态按钮或改标签，具体按 acceptance.md 验收。

## 正文编辑与渲染

正文分块语义在初始化导入、后台编辑、未保存预览与前台输出之间一致。纯文本加有限格式时按行识别小标题、段落、项目列表和编号列表，不依赖标题后必须有空行；标题只取当前行，类型切换及时结束上一块。空行、CRLF、连续列表、列表后普通段落和 HTML 特殊字符均有明确处理。保留文字与顺序，不把内容当成可执行 HTML。

优先共用解析逻辑；前后端分别实现时使用同一组输入和预期语义做回归。打开旧内容、只改无关字段再保存，不得把标题后的正文合并到标题或丢失列表。预览真实展示当前输入、当前新选封面，不读取旧缓存冒充预览。

## 内容工具的生成要求

为当前项目生成工具，并与实际数据表、权限和配置对应。可采用 CLI 方式提供：

- init：只在未初始化的项目创建管理员，初始账号 admin、密码 123456，存储密码哈希；已有配置不覆盖。
- plan：读取当前内容，列出新增、改变字段的前后值、公开范围和冲突。
- apply：确认计划与输入、站点和数据库版本一致，在事务内应用。
- export：导出当前内容、来源及合并时需要的基线。
- catalog：只导出公开目录。

命令名可按项目调整，但 README 中的示例必须对应真实生成的文件和参数。计划、内容包与导出保存在 public 之外；不把凭据写进命令参数或报告。

## 并发与更新

使用稳定内容标识和网址。先读取人工编辑，再合并新需求；包中未涉及的内容保留。不得通过删除重建整库完成更新。

表单提交、导入计划与导出需要一致的数据版本。过时表单不能在报错后自动获得新版本并覆盖其他人的修改。批量写入采用事务，失败时回滚；文件与数据库共同变更需处理失败后的清理或恢复。

修改网址需单独列出影响与重定向方案；实际跳转按环境生成和验证。删除同步关闭公开正文、导航入口、关联链接、目录和 sitemap，外部索引与访问者副本另行解释。

## 共用基础组件

登录、权限、上传、保存和缓存优先复用来源明确、适用于本技术栈且有实际验证依据的组件。可以复用已有项目的小模块，不要求安装框架、CMS 或整套后台。没有合适组件时按本规范生成实现，状态记为待验证。

在 site-plan.md 记录各组件的职责、项目内位置、来源、版本或代码摘要、许可、依赖、已测环境与证据、负责人。自行生成的模块也登记实现位置及验证范围；不能将语言内置函数、别的项目通过或“使用成熟组件”当成本站集成通过。固定业务语义与接口，企业栏目和字段保持可变。集成后检查保存、删除、权限、缓存和恢复，依赖升级或模块改变时复查受影响路径。

## 公开页面缓存

首版选定一种可部署的主要页面缓存方式。普通 PHP 主机可采用 public 外的文件缓存；具备维护条件时也可采用受控反向代理缓存。记录实现位置、缓存键、有效期秒数、命中判据、失效入口和故障处理，不以“已开启缓存”代替实际实现，不默认增加 Redis 等服务。OPcache 缓存 PHP 字节码，不能代替公开 HTML 缓存。PHP 配置或代码变更后，按实际 Web 进程的重新验证策略等待生效或授权刷新进程，再用 HTTP 核对；文件已写入不等于当前请求已采用新配置。缓存与生产/预览边界测试使用独立实例及配置，不切换正在使用的站点；测试结束核对原实例仍保持原访问和索引限制。

缓存规则必须进入代码与服务器配置：

- 只缓存允许公开的匿名 GET 页面成功响应；HEAD 保持同样的状态与响应头语义且无正文。后台、登录、预览、私有媒体、写请求、错误响应，以及含身份或个性化状态的请求/响应均旁路公共缓存。
- 登录 Cookie、Authorization、预览参数及 Set-Cookie 需要明确排除；不能把含 CSRF、会话提示或未公开内容的 HTML 写入匿名缓存。登录与预览响应设置 `Cache-Control: private, no-store`，代理层同样排除。
- 缓存查找前完成路由、公开状态与旁路判断。应用缓存存储不作为可直接访问的静态目录；代理缓存要有对应排除与删除策略，避免绕过 PHP 的权限检查。
- 缓存键包含站点、规范路径、会影响内容的已允许参数、内容与模板版本；模板版本覆盖正文解析器、共用渲染函数及会改变输出的配置，不能只取主模板的修改时间。分页或筛选不能串页；未知参数按路由拒绝或旁路，不任由参数生成无限缓存。站点来源使用可信配置，不从任意 Host 头生成 canonical 或共用缓存。
- 匿名浏览器的 HTML 默认每次复用前验证，例如 `Cache-Control: no-cache` 配合正确的 ETag 或 Last-Modified；应用内部仍可使用页面缓存。静态资源采用内容版本 URL，设置适合其可公开范围的缓存期限。需要共享代理/CDN 缓存 HTML 时另写清 TTL、清理权限与最大生效延迟。
- 缓存使用原子写入、受控路径和大小/过期清理。通过内容代次、锁或同等机制防止旧请求在发布后把旧 HTML 写回当前缓存。条件请求的校验值随可见内容变化，修改后不能错误返回 304。
- 用响应头或服务日志标明实际 HIT / MISS / BYPASS 及缓存层，不输出私有路径或凭据。缓存读写故障可安全回退动态公开页面，必须记录异常；不得回退为泄露私有内容或继续提供已删除正文。

## 保存、缓存与目录的一致性

后台编辑、内容导入和恢复使用共用变更服务，避免其中一条路径漏掉缓存。把内容与公开范围、关联和失效任务在事务中一致保存；数据库提交与外部缓存清理不是一个可自动回滚的事务，要分别反馈。

| 变更 | 需要重新生成或失效的范围 |
|---|---|
| 公开内容与摘要、SEO 字段 | 详情、类型/分类/分页列表、引用该内容的首页与关联页、JSON-LD、sitemap、公开目录 |
| 保存、删除或来源许可变化 | 上述页面及导航、推荐、双向关联；删除正文的源站和已启用 CDN 缓存 |
| 企业名称、联系方式、Logo | 使用该字段的共用组件及页面、对应结构化信息、媒体变体和资源引用 |
| 图片替换或说明改变 | 原使用页面、缩略图及变体引用；新资源用新版本 URL，不能只覆盖同名文件后假定浏览器更新 |
| 网址迁移 | 新旧地址、已允许的重定向、内部链接、canonical、目录和 sitemap |
| 数据恢复、模板或配置更新 | 与恢复状态或模板有关的全部缓存与目录，必要时切换全站缓存代次 |

实施顺序为：核对权限与版本 → 校验公开条件 → 保存内容及失效记录 → 提交 → 处理缓存和目录 → 匿名回读并记录。小型站点可用全站缓存代次失效实现正确性，说明代价；有依赖索引时再精确失效，不需要为了首版搭建复杂队列。

后台以“内容是否保存、网站页面是否更新”反馈真实结果。数据已提交但缓存清理失败时，显示“内容已保存，部分页面暂未更新”，列出受影响的页面名称和“重试更新”或联系维护人员的动作，不只弹“发布成功”，也不误称数据未保存导致重复新增。技术原因、失败时间、范围及负责人保留在私有维护记录中，失败任务可持久查询和安全重试，重试不能重复插入内容。

删除后源站立即阻止读取正文；对已配置 CDN 逐项执行清理并核对实际响应。CDN 不具备可靠的删除或旁路能力时不启用其 HTML 缓存；已有清理失败时按其能力停用对应缓存或阻断边缘路径，并把仍可访问的副本列为失败项。新加 no-store 不能清掉已存缓存，不承诺追回访问者已下载内容。

回读使用原有公开 URL、无登录 Cookie 的请求，比较正文、状态、版本及实际缓存层；新查询参数、强制刷新或登录预览不能替代普通匿名访问验证。源站与 CDN 分别记录。具体检查任务见 acceptance.md。

## 联系表单与咨询管理

新站默认实现 references/inquiries.md 的后台优先接收流程。联系表单与账号设置不是素材充分才出现的内容栏目；没有收件邮箱仍需保存和管理咨询。账号设置提供当前密码、新密码、重复确认、错误反馈与保存后退出重新登录；修改密码需验证当前密码，新密码至少 6 位，两次一致。初始密码与数据库密码、SMTP 授权码分别管理，不能混用。

## 基础安全规则

- 使用 password_hash / password_verify 等标准密码能力，PHP Session，生产 HTTPS，安全 Cookie 和会话轮换。
- 写操作采用 POST、登录权限和 CSRF 校验；所有 SQL 值参数化。
- 对输入类型、长度、枚举、标识、媒体引用与关联对象作服务器校验。布尔字段不能靠字符串真值推断。
- 输出按 HTML、URL、JSON 等上下文处理，结构化信息与可见事实一致。
- 上传限制大小、像素与类型，核对实际 MIME 和图片结构；随机文件名，不接受可执行内容。
- 未公开媒体按权限读取，公开素材不承诺可从所有缓存追回。
- 外部监测链接不含密码、令牌或 Cookie；不自动登录，不嵌入无授权统计。
- 本地 HTTP 例外仅限 localhost、127.0.0.1 或 [::1]，并需显式开发模式；其他主机仍要求 HTTPS，拒绝协议相对地址及带用户信息的 URL。
- 生产错误页面不暴露连接信息、堆栈和私有目录；维护日志不得记录凭据。
- 修改密码分别提示当前密码错误、长度不足或两次输入不一致，提供显示/隐藏密码，保存后说明需要重新登录。
- 下载和 CSV 导出在页面模板输出之前执行，返回正确的 Content-Type 和附件响应头；文件不得混入 HTML、导航或错误信息。

这些是生成与验收要求。每个生成项目都需单独验证，不能把规则存在当成代码正确。
