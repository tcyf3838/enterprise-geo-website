# 工作流程

按用户要求选择任务路径，明确允许做到资料整理、生成文件、运行验收还是公开部署。讨论和审阅不自动触发后续执行。

## 顾问项目简报

以企业当前问题组织任务，记录客户现状与所选场景、业务目标、目标受众、访客行动、已确认资料、现有站点和权限、当前交付阶段、完成依据及排除项。顾问组织实施，企业确认业务事实，运营维护日常内容，技术人员负责环境与故障。可合并进 site-plan.md 或诊断报告，不要求运营另填技术表。

能从资料确认的内容直接采用；只追问影响本阶段判断或动作的缺口。不把“要做 GEO”当作完整目的，也不在缺少平台回答时编造 AI 当前认知。若用户已有题目或诊断结果，关联到具体页面和内容；没有时按业务问题规划，不自动启动额外 AI 平台测评。

资料准备按 [推荐输入](#推荐输入) 核对：先明确企业、场景、要解决的问题、交付阶段、资料位置与完成依据，再按需要盘点十类企业资料及本场景补充项。复用现有文件和知识库，记录已提供、当前缺口及何时补齐；联系入口同时明确接收人和处理渠道，后台字段结合日常维护需求设计。仅诊断不要求先交源码或数据库，部署资料不阻碍已授权的方案工作。

## 新建官网

项目资料与知识库检索 → 来源登记与事实映射 → 业务理解及页面字段规划 → 真实官网视觉参考分析 → 全站主题、区块节奏、图片与动效方案 → 首页与代表性详情的桌面/手机制作、查看与修正 → 扩展全站并完成 PHP 后端、MySQL 结构、公开缓存与 SEO/GEO 输出 → 在授权环境配置初始化 → 导入确认内容 → 前后台与全站视觉验收、缓存及代表页性能检查 → 集成内置监测并回读请求、事件和报表 → 使用维护交接。

生成前说明模块取舍，生成时落实实际代码。部署条件未提供时可以先完成文件和安装说明，不声称网站已运行。

生成后按 acceptance.md 的每站自查流程交叉核对页面、功能和资源，分层检查、修复并复查共享影响及关键链路，按本阶段必查项判定交付；不能把首页正常或 HTTP 脚本通过当成全站通过。每站自查与 Skill 评测中的两套资料、独立试用和方法对照分别记录，后者按约定的评测范围执行。

完整建站默认按 native-monitor.md 同步生成内置模块和部署说明，检查迁移、可信代理、维护任务与观察范围。只改文档或明确不运行时不启动服务。只有明确选用原版 GEOInflow 时，再按 geoinflow.md 走独立部署流程。

## 本方案网站维护

登录后台进行日常编辑、查找、新增、编辑与删除。用户要求 Skill 批量更新时：

1. 读取当前项目、数据库内容、人工修改和公开网址。
2. 对照新事实，列出受影响的字段与页面，保留无关内容。
3. 备份并形成可审查变更计划，处理冲突。
4. 在授权范围应用，刷新受影响的公开缓存、SEO 输出、目录和 sitemap；检查保存与缓存处理状态，以原 URL 匿名回读正文、联系方式和关联，已启用 CDN 时另核对边缘。失败按 native-php.md 跟进，不只看登录预览。
5. 在内置访问监测核对当前目录范围，使用可比窗口观察访问。

更新结束按 acceptance.md 复查原问题、变动涉及的模板/内容/缓存及关键浏览或保存链路，记录最终版本与仍未检查的范围；条件未变的无关有效检查不必全部重跑。

内容更新沿用当前主题和共用组件。涉及改版时先读取 theme-plan.md 与实际样式，明确受影响页面，不能只改首页导致其余页面风格断裂。

## 中断后继续

在既有项目方案、交接记录或新站私有 delivery-status.json 中保留当前阶段、产物位置及版本、已完成与未完成项、失败原因和下一步，不额外建立一套进度系统，不记录凭据。

1. 继续前读取当前授权范围和上述记录，再核对相关实际文件；涉及已授权的数据操作时读回数据库状态。确认最近完成的步骤、尚未完成的动作，以及中断后发生的人工修改和环境变化；记录不是完成证据，缺少记录时从现状重建必要进度，不猜测成功。
2. 保留已完成且仍有效的产物，从剩余步骤继续。写入前备份并检查冲突，不重新生成整站覆盖人工编辑，不重置管理员、清空数据库或重复导入。导入使用项目稳定内容标识判断新增与更新；上次操作结果不明时先回读，再决定补做、回退或重试。
3. 已完成的素材生成、付费调用与部署动作不自动重复。缺少恢复条件时记录具体阻塞，继续独立工作；“继续”沿用原任务授权，不扩大到原本未授权的运行、购买或公开部署。
4. 完成后更新同一份记录，复查失败项、实际变动及其关联链路；条件未变的有效证据可复用。尚未执行的检查保持未执行，不因恢复工作而改成通过。

## 旧站诊断与局部改造

从项目简报确认改造目的，再按实际可访问范围检查内容、业务路径、主题和图片、后台维护、机器可读正文和链接、索引与响应、缓存、监测及运行环境。记录网址、页面类型、内容来源与检查条件；不可见的后台和服务器状态保持未知，不能从页面外观推断实现。

在诊断及改造清单中逐项记录问题位置、证据、业务影响、建议动作、优先级、需要的源码/数据/账号条件、保留项、实施人和验收方法。优先级按影响与依赖说明：阻碍核心信息、操作或访问的先处理，体验优化和长期建设另排；不机械给每站同一清单。

只有网址或其他技术栈时交现状诊断与可执行建议，不自动下载私有数据、改站、迁移或重建后台。同为 H5＋原生 PHP＋MySQL 且有授权源码和数据时，先核对路由、字段、公开范围、权限、缓存与人工定制，按维护流程备份、实施、回读并复查受影响链路。实际可实施的范围由代码和依赖决定，不只凭后缀名判断兼容。

保留无关内容、人工编辑、有效网址和配置；需要改变网址时给出逐页对应关系，验证真实跳转与原有入口。缺少权限仍可完成有证据的诊断。交接分别列已诊断、已实施、已复查和未实施项；不以建议交付代替修复完成，不把未改动的后台或监测列为本次通过。

## 多站信息一致性梳理

先盘点站点与资料范围：域名、用途、所属法律主体与品牌、面向地区/业务、内容责任人和可修改权限。主体关系以企业确认资料或可信公开依据为准；相近名称或同一集团不等于同一主体，资料不足记录待确认。

按代表页与现有目录逐站核对，说明抽样范围和未检查页。形成以下内容，可合并到一份多站信息一致性梳理报告：

| 交付内容 | 必要信息 |
|---|---|
| 站点职责与关系 | 网站、主体、品牌关系、业务和地区范围、联系人及权限；关系依据 |
| 共用事实 | 字段、适用主体和站点、确认值、来源与日期、确认人 |
| 合理差异与冲突 | 各站实际值及网址、属于真实业务差异还是冲突、双方依据、待确认问题 |
| 逐站修改建议 | 目标页面、建议内容、依据、优先级、实施条件、责任人、验收办法与状态 |
| 梳理结论与交接 | 已检查与未检查范围、已确认事实、保留差异、待确认冲突及下一步 |
| 实施与复查（包含修改时） | 实际改动、备份回退、匿名回读与关联输出检查；逐站记录未实施项 |

共用名称、品牌关系和联系方式仅在适用范围一致时统一；不同法人、分支、地区服务、产品和资质保留真实差异。确认冲突前不选一个值全站覆盖。页面、元数据和结构化事实保持同一口径，不为制造“统一”而复制全站正文、把不同页面一律规范到主站，或混用不同主体身份。

执行修改时逐站进入旧站路径，分别核对授权、备份、数据、配置、缓存和验收；不默认批量写入、不合并数据库、不强制迁域名。集中管理后台和自动同步另定范围。交付目标是对外信息一致和关系清楚，不承诺 AI 合并收录；各站访问观察独立，目标平台对主体的识别需另有真实回答证据。

| 信息 | 建议说明 |

### 三种场景分别补充什么

| 使用场景 | 推荐补充资料 |
|---|---|
| 新建官网 | 希望优先展示的业务、栏目与功能；已有品牌规范和参考官网；是否已有域名、主机、备案信息及维护人员。准备部署时再补充资源条件、预算与上线安排 |
| 旧站诊断与局部改造 | 现有网址、重点页面、问题描述、必须保留的内容和功能，以及已知技术栈、后台能修改的范围。进入实际改造时，再提供相应源码、用于验证的数据、备份、环境信息与授权范围 |
| 多站信息一致性梳理 | 各站域名与用途、所属企业和品牌、面向地区与业务、内容负责人及可修改范围；共用信息的确认资料、允许存在的业务差异、已发现的冲突及对应页面。需要改站时逐站补充实施资料 |

**提供方式与补齐顺序**：资料保留原文件，直接给出路径或链接；Skill 先盘点已有内容，再归类、提取并列出缺口。上面的清单按企业业务和当前阶段选用，通常可先从企业介绍、核心产品或服务、客户问题及现有素材开始。缺少案例、测评结果或服务器资料时，先推进有依据的内容，按需要补齐；正式公开前核对业务事实、素材许可和联系入口。账号、密码和密钥在实际接入时单独交接。

教学或脱敏样例用于本机或经过鉴权的受控预览，并禁止索引；样例性质在交接材料中说明，不默认添加官网访客横幅。正式公开前核实或移除样例事实与占位入口。

## 资料处理

### 整包资料接收与整理

先查看目录和压缩包清单，保留原件，在项目私有资料区整理可读取的副本；解包路径须位于该目录内，不执行包内程序，也不覆盖已有项目。加密、损坏、格式不支持或无法访问的材料标为未读取，说明对当前任务的影响；不能把“文件已收到”写成“全部已读完”。

在既有来源记录中盘点文件用途、版本、主体及读取状态。重复文件可合并引用但保留原件；同名不等于同内容，修改时间也不代表已确认的新版本。优先采用企业指定的现行资料；数字、联系方式或业务条件冲突时保留对应出处，只追问影响本阶段使用的部分。

实际查看拟使用的图片和文档页面，判断照片、海报、证书、Logo 与示意图各自用途，不凭文件名推断内容；OCR 提取的关键名称、编号和数字应对照可辨识原文核对，不清晰则标为待确认。素材尺寸、裁切和版权按 design.md 处理，视频只报告实际查看的范围。

将可用事实和素材归入现有 content-map.md、页面方案及素材清单，说明用于哪个页面、支持什么陈述、是否可公开；内部资料、过期版本与重复素材不自动进入网站。不为接收整包资料增设后台栏目或多套登记表，先交可用内容、页面对应和关键缺口。

### 检索与事实核对

检索按以下顺序开展，用户明确限制信息来源时遵从其要求：

1. 项目当前资料：确认使用版本、品牌事实、目标客户、业务和公开范围。
2. 可访问知识库：检索品牌名及别名、行业、官网主题、视觉、案例与相关方法。优先看索引和当前结论，再按需要打开原文；归档、历史提案和外部摘录分别识别。
3. 网络一手来源：新建或改版时主动搜索并查看业务、受众或访客任务相关的官网，比较全站风格与内容布局，按 design.md 形成判断；同时补充资料缺口，核对可能变化的事实。设计参考记录原站、查看范围和具体取舍，不复制其正文、商标或未经授权的素材。

在 sources.md 中记录检索范围、实际读取的文件/网址、版本或日期、来源性质、用途及未解决问题。未找到也简要注明，避免反复检索；知识库不可访问时说明限制，可继续完成不依赖该资料的部分。知识库内容可能过时，网络内容也不自动优先，冲突要核对主体、时间、依据与本次使用范围。

从使用者提供或授权访问的知识库开始，优先查阅当前索引、行业方法、品牌资料和官网建设研究，按实际可用的文件位置或连接器读取。无须每次遍历全库，只读取与当前判断有关的材料。

原件保留。来源记录稳定 ID、标题、位置、主体、日期（若有）、确认和公开范围。没有日期不推断新旧；已提供不等于已核验。

缺失与冲突进入私有清单。教学数据在内部保留 demo 状态并限制在受控预览环境，正式访客页面不自动展示教学、核验、裁切或开发说明；样例性质向审阅人单独说明，正式发布前按 content-model.md 核实或移除样例。栏目数量、页面数量和字段取决于业务，不为完整外观补造案例、文章或经营数字。
