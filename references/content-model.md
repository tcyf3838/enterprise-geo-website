# 内容语义与输入约定

前台、后台和导入工具共享一套内容语义。数据库表结构由 Agent 按项目生成，字段映射写入 site-plan.md；同一个字段不能在导入、后台和前台中有不同含义。

## 从资料到模块

先回答顾问项目简报中的客户问题，再按“问题—事实—来源—页面—字段—行动”映射。企业介绍用于确认主体和范围，产品手册用于参数及条件，真实咨询记录用于问答，案例资料用于说明动作与结果；缺失、冲突、公开权限和编辑推演分别记录。

例如介绍、手册和客服记录共同描述一项服务时，整理主体、适用对象、交付内容及条件，进入服务详情与后台字段；问答关联该服务。两份资料的交付周期冲突时保留双方依据，不取平均值或擅自确认。该例是方法说明，不能当成企业事实。

| 模块 | 回答的问题 | 启用条件 |
|---|---|---|
| 企业介绍 | 谁提供业务，主体与品牌如何关联 | 有确认的主体、范围及共用信息 |
| 产品或服务 | 能解决什么，适用谁，有何条件 | 核心业务有依据，适合独立详情与维护 |
| 解决方案 | 某场景怎样处理 | 场景、方法及对应业务足够完整；否则并入相关详情 |
| 案例与证明 | 有什么相关经验与证据 | 有允许公开的动作、结果和出处，不凭空补齐 |
| 问答与文章 | 选择、使用或合作时有哪些疑问 | 有事实支撑及独立阅读价值，候选问法不冒充真实高频咨询 |
| 联系与咨询 | 访客接下来如何行动 | 有真实可用的入口或接收流程 |

模块选择写明解决的客户问题、资料依据、独立或合并的理由及后台维护字段。页面数量由内容决定；没有资料不生成空模块。旧站保留适用的现有栏目，多站共用信息按主体与适用范围核对，不能合并不同主体的事实。

## 面向搜索与 AI 回答的内容组织

先把客户决策问题和已有搜索查询归并到页面职责；同一意图的不同问法可以由同页回答，已有页面能承担时优先完善。按需求组织企业身份、产品/服务、适用场景、选型比较、实施或使用说明、案例证据及联系入口；内容不足时合并或暂不启用，不按关键词变体批量造薄页。

重要页面应能独立说明“谁提供什么、适合谁、在什么条件下、依据是什么、下一步怎么做”。先给读者需要的回答，再展开参数、流程、比较、限制或问答；选择适合内容的段落、列表与表格，不强制固定字数、问答数量或切成细碎页面。标题和段落中明确实际主体、产品及版本，避免代词不明或把关键限制藏在其他页。

优先提取企业确有的产品实测、项目过程、专业经验、原创数据及图片，说明适用条件、时间和可公开依据；相比泛泛介绍，增加哪些有用信息应在页面方案中说清。数字与案例结果逐项对应资料，不将相关性写成因果、将个案写成普遍效果或为满足结构编造材料。公开引用链接指向真正支持陈述的来源，企业自报与第三方证明区分；原始资料内部可查不等于可以公开原件。

页面内容、实体标识与结构化关系按 deployment.md 的 Schema 映射生成，同一事实只维护一个来源。多站核对共用主体和合理差异，真实门店分别核对地址、电话、服务和资质；外部官方身份资料存在冲突时列建议，站外发布或账号修改依本项目权限和约定执行。

目标问题、对应页面、事实与待观察变化可以直接写入 content-map.md。提及、准确性、官网引用和访问的后续验证见 deployment.md；没有平台回答就按业务需求规划，不宣称已发现 AI 错误或已提高引用率。

### 将能力说明落到具体证据

企业能力不能只剩“专业团队”“多项专利”或醒目数字。按实际业务和资料选取有助客户判断的事实，让概括性说明能对应到可核对的明细；并非每家企业都需要研发、专利或资质专区。

| 宣传内容 | 页面中可采用的事实与依据 |
|---|---|
| 专利或技术成果 | 真实名称、编号、权利人、资料确认的状态及日期，说明与业务的关系；申请与授权分清，有可核对的公开链接时提供，不从证书照片推断当前有效状态 |
| 资质、检测或认证 | 名称、主体、发证或检测机构、适用产品/业务范围、有效期或报告日期；标识和图片对应实际获准使用范围，不扩大为全部产品或集团的证明 |
| 团队与专业能力 | 可公开的岗位、专业经历、分工与具体成果，必要时附真实人物或工作图片；不从合影人数推算团队规模，不虚构头衔或研发能力 |
| 案例与经营数字 | 项目背景、具体动作、结果、统计时间和口径；数量说明单位、去重方式及适用范围，区分自有、合作、累计与当前，不将材料条目数当作业绩 |

关键事实写入可读的 HTML 正文，图片承担展示、辅助理解和必要证明作用，不能让访客只能从证书图或海报辨认业务条件。按公开许可展示摘要、明细或附件，允许引用事实不等于允许公开原件。只展示部分项目或专利时说明是代表性内容，不冒充完整清单；汇总数字必须有实际统计依据，不能由抽样条数推算总量。

这些内容优先放在对应业务、案例或企业介绍页；有独立阅读价值时再建详情。后台沿用相关内容的中文表单、列表或附件，不增加独立“证据管理”工作流，也不要求运营维护来源 ID。同一事实共用数据；事实、有效期或适用范围改变时，复核引用它的首页、详情、摘要、汇总数字和适用的 JSON-LD，不能只换图片而保留旧承诺。

## 内容包

参考内容包采用 schema_version 字符串 2.0，包含 site、sources、media、records。它是整理后的输入，不是某套预装后台的数据库备份。

site 包含 name、tagline、summary、phone、email、address、contact_url、brand_color、accent_color、focus（product/service）、demo（布尔）、logo_key、source_ids。联系方式未提供时留空；logo_key 为空表示未提供 Logo。监测密钥、可信代理与可选 GEOInflow 地址属于私有环境配置，不能混入企业对外简介。

sources 每项包含 id、title、locator、confirmed、public_allowed；可增加主体、日期与范围说明。确认与公开许可为 JSON 布尔值。locator 及来源原件默认私有，允许公开事实不等于公开内部资料。

内容包的 sources 用于支持具体企业事实、行业事实或素材授权，例如企业确认的介绍、产品手册、资质文件及图片许可。建站教程、知识库中的设计方法、参考官网和开发文档属于制作参考，按用途登记在项目私有来源记录、theme-plan.md 或技术说明中，不因“已读取/已确认”就成为企业参数、资质或服务承诺的依据。初始化和导入时区分这两类用途，不把制作参考混入正文的 source_ids。

来源与确认状态属于内部数据，不生成独立“来源/资料依据”栏目。资料整理、初始化和导入建立事实及素材的对应关系，日常编辑复用适用依据；新增或改变事实时只复用实际覆盖该事实的记录，不能沿用无关的已确认状态。企业人员确需补充材料时，在对应内容表单中提供附件或备注入口及具体缺项提示，不要求手工填写来源 ID 或另走一套登记流程。系统在私有记录中保留事实、来源与关联内容的对应，供维护人员处理更新或许可撤销；不得因简化界面自动把未确认内容设为已确认。

经授权的企业维护人员在正常表单中确认本次输入并保存的自有业务信息，可在内部登记为企业录入资料，保留操作者、时间、内容和确认范围，无需再填写一份来源表。这表示企业自报，不能冒充第三方证明或覆盖已有材料冲突；涉及资质证明、外部引用或素材授权时仍使用相应实际材料。导入成功、模型生成或保存教学样例不算企业确认。正常企业维护人员保存的自有业务输入可按实际范围登记，不要求额外发布步骤。

confirmed 表示该用途下的事实已确认，不表示外部认证；public_allowed 表示关联事实或素材可用于公开内容，不自动授权公开原文件、内部路径或联系人信息。此处字段是生成与导入约定，不是后台表单清单；运营界面的名称、控件和自动处理方式按 native-php.md 映射。

media 为素材列表，每项使用稳定 key、项目内素材位置 path、alt 说明、source_ids 和 public_allowed。没有素材时使用空列表。只引用实际存在且允许使用的文件；读取素材时检查路径位于授权目录内，不执行其中内容。数据库媒体 ID 在项目初始化时建立，不能在通用内容包中猜测。

素材删除需明确确认，随后实际删除本站媒体文件、关联衍生文件和素材数据库记录；默认不保留回收站或恢复状态。所有未删除内容及共用图片字段参与引用检查，存在引用时先要求更换或解除。缺省或缺失的导入记录不代表删除指令；外部原始材料与独立备份不属于媒体库删除按钮的范围，不能混称已经全盘销毁。

按项目需要增加 kind（摄影、产品、人物、海报、证书、标识）、原始尺寸、fit、焦点位置、允许裁切范围及桌面/手机变体。适配规则落到实际模板，不只写入文档。区分供访客阅读的 caption 与仅供维护的 internal_note；alt 描述图片内容与用途，不填制作过程、内部文件名或裁切理由。没有有用图注时不强行输出。

Logo 素材记录真实透明度、适用背景、品牌安全距离，以及原件与衍生文件的对应关系。项目确需深浅背景版本时，使用关联的素材 key 并记录用途，不硬编码多套无来源图片。没有变体需求时不强制增加字段。换图时同步检查页头、页脚和各状态引用，内部处理记录不输出到前台。

records 每项：

| 字段 | 语义 |
|---|---|
| key | 稳定内容标识；英文、数字、下划线或横线，1–80 字符 |
| type | product / service / solution / case / faq / article / page |
| title | 标题 |
| slug | 稳定网址末段，小写英文、数字或横线，最多 120 字符 |
| content | 基础正文，参考样例为纯文本、空行分段 |
| excerpt | 页面摘要 |
| status / deleted_at | 内部有效或删除状态，不生成日常流程控件；可用 active/deleted 或等效字段。兼容旧 published/draft/hidden 时保留真实可见性，不自动公开历史记录 |
| confirmed | 正文事实确认状态，布尔值 |
| source_ids | 关联来源 ID |
| related_keys | 相关内容的稳定 key |
| role | 空字符串，或 page 类型的 about / contact |
| cover_key | 素材 key，空字符串表示无封面 |
| category | 文章栏目稳定标识，如 news / tutorial / qa；其他类型按项目需要使用，可省略 |
| resources | 补充资料数组，每项含 title、url、kind、source_ids；kind 为 document / video / link，可省略 |
| fields | 按业务需要增加的结构化字段，可省略 |

业务字段由材料决定，例如产品接口、适用条件、服务交付范围。字段的名称、类型、必填性、单位、后台控件、前台展示和来源要求写入映射表，再生成数据库与代码。

solution 表达客户场景、问题、处理方法和限制，通过 related_keys 连接已有产品或服务、案例和 FAQ；只有材料足够才独立成页。产品、方案与文章之间的关联使用稳定 key，不在正文里写死数据库 ID。文章栏目及显示名称统一维护。

resources 只引用真实存在、允许公开且已核对的补充资料。网址采用允许的 HTTP(S) 协议；项目内附件经公开权限检查后提供访问路径，私有文件不因被引用而自动公开。未提供文件时列缺口，不编造下载链接。手册和视频不能代替可读的业务正文。

默认首发时间由首次保存并可公开的操作写入，更新时间由实际内容修改写入。迁入已有内容时，只有来源确认的历史时间可保留，缺失则说明缺失，不倒填虚假日期。

## 页面元数据与派生输出

在 site-plan.md 映射每类页面的标题、摘要、规范网址、索引策略、结构化类型及来源字段。可用 title/excerpt 生成基础元数据；需要运营分别维护时增加 seo_title、seo_description 等字段并明确回退规则，不要求所有项目增加相同字段。canonical 从可信站点地址与稳定路由生成，不能把任意输入当站外规范地址。

JSON-LD、列表、推荐、关联摘要、公开目录和 sitemap 都由当前公开数据生成，不另存一套人工维护的企业事实。组合页面的更新时间依据实际可见内容变化，缓存重建不改首发或内容日期。后台修改及导入要能识别这些输出的依赖，按 native-php.md 失效缓存并在 deployment.md 的 SEO 规则下回读。

缓存代次、失效任务与运行状态属于项目技术数据，不混入企业经营事实或公开简介。撤销来源许可、删除记录及恢复数据时同步处理依赖页；不能仅修改删除标记 而继续返回旧缓存。

## 发布规则

公开内容需有实质正文、事实确认和存在且允许公开的来源。企业共用信息同样有来源。待确认材料保存在私有资料或当前未保存输入中；不为此增加默认草稿工作流，输入缺失或矛盾时不能为了通过校验而改成已确认。

关联内容必须存在；前台仅显示已发布目标，需要互链的关系两端都设置。Logo 与封面仅使用实际素材，素材说明可在后台后续编辑。

页面与后台栏目按业务启用；类型枚举不意味着每家企业都必须生成全部栏目和空页面。

## 访客内容与内部说明

公开模板只读取允许公开的事实、业务文案和必要的产品使用提示。来源许可、核验状态、冲突说明、设计选择、裁切理由和测试状态留在项目私有记录中；管理后台只在影响具体操作时提供简短、可理解的说明，不生成专门的技术状态栏目，也不自动拼到页头、页脚、卡片、图注、alt、页面描述或 JSON-LD。依法需要的产品提示、隐私说明及授权署名照常保留。

默认不生成“教学演示站”“脱敏资料”“统一教学口径”“不代表重新核验”“演示占位”“待补素材”等前台文案，也不靠隐藏 CSS 保留这些可被读取的内容。必要的操作反馈按真实行为显示；无真实电话、邮箱或二维码时省略相应直接联系入口；默认以后台咨询数据库作为真实接收流程，生成联系表单与咨询管理。收件邮箱缺失仅影响可选通知，不影响表单保存。数据库暂不可用时明确提示未保存并保留输入，不能显示虚假提交成功。

demo 是资料与运行状态，不是主题元素。教学样例保持 demo=true，使用仅本机或经鉴权的受控预览，并设置禁止索引；noindex 不能代替访问控制。样例性质告知审阅人并写入私有交接说明，前台视觉预览保持正式页面样式。只有用户明确要求课堂演示标识时才显示，并与正式发布模板分离。

正式发布须核实或移除教学事实、占位数据、未确认承诺及假入口，再按实际情况设置 demo=false。正式发布流程遇到 demo=true 或未处理的样例内容应阻止发布，并在相关操作处用普通中文说明具体原因；不要求运营手改标志，也不允许仅删除横幅或改标志就把样例当成真实企业事实。

## 更新约定

更新先读取当前数据与人工修改。使用稳定 key 定位内容，保持网址；只改变本次确认的字段。缺省字段和未包含记录不自动删除。删除使用明确指令和版本检查，优先内部软删除，未包含记录不等于删除。

计划列出字段前后值、公开范围、关联影响和冲突。生成工具可采用版本号、内容摘要等记录基线，并将计划绑定站点、输入和当前状态。并发变化后重新合并与预览，不强制覆盖。

导出基线由当前项目实际生成，不伪造。合并时保留人工内容和未涉及字段；基线匹配只说明版本一致，不能代替业务核对。

## 公开目录

生成 sitemap 和 public-catalog.json；内置监测直接使用同源发布目录，不依赖手工导入。明确启用 GEOInflow 时也可使用该公开目录。JSON 使用顶层条目数组，不加自有 records 等包装层，并在接入时核对安装版本的导入要求。条目使用 url、type、title，可提供有真实依据的 publishedAt、updatedAt、source。只含当前已发布、可公开访问的页面，首页单列；不包含未公开内容、预览、后台和私有素材路径。sitemap 进一步只保留应索引的有效规范页；若公开监测目录与索引目录范围不同，在私有说明中记录分母与理由。

另在项目私有资料中登记重点页面及其业务用途。内置报表使用当前目录分母，外部工具的统计目录范围另行核对，不能把私有重点清单自动当成工具覆盖率的分母。

新增、修改、删除后更新网站自身目录。启用可选 GEOInflow 时，其目录需要按接入流程核对；导入缺少某条旧记录并不自动证明远端已经删除。
