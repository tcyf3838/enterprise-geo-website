# 全站视觉设计与前台生成

目标是有品牌辨识度、有美感且可正式使用的商业官网。主题包含配色、字体、图片、布局、组件、动效和手机体验；后台共用同一 PHP 业务层，不限制前台表达。依据企业、受众和素材设计，不设固定行业类别或主题套装。

## 从资料到设计方向

新建或整体改版时执行；日常内容更新沿用已确定的主题。

1. **先读业务和素材。** 明确主要访客、真实业务、核心问题、希望发生的行动、品牌气质和可用内容规模。查看图片原件，判断素材能支撑什么构图；不能只读文件名就安排主视觉。已确认品牌规范与用户偏好优先。
2. **检索真实参考。** 先查项目与可访问知识库，再搜索并打开实际官网。通常选 2—3 个有比较价值的参考，确有未覆盖的设计问题时再补充：覆盖相近的访客任务、优秀的视觉表达和可用的交互方式，可以由同一网站同时满足。设计画廊只用于发现原站，不能拿搜索摘要或缩略图当成已研究。避免只看同一种技术产品模板；根据企业需要查产品品牌、机构、服务、制造或内容型网站，不把这些当作固定类别。
3. **看页面，也看浏览过程。** 查看首屏、连续多个区块、页尾和代表性内页，有条件时检查手机与实际滚动。逐项记录构图、图像占比、标题比例、背景变化、内容深度、动效如何帮助理解，以及不适合本企业之处。区分文本读取、截图查看、滚动观察和实际操作；没有看的不写成已经验证。
4. **决定视觉方向。** 将“资料依据 → 访客需要 → 设计选择”连起来。方向不明时按下方样稿要求比较两个在构图、字体、图像和浏览节奏上实质不同的方案，再按材料和偏好选定；不要只给不同颜色。同一行业也可有不同表达，不从企业名称直接猜风格。

参考网站的文案、图片、品牌事实和商标不能随设计借鉴复制。知识库或网络不可访问时，在私有方案中记录实际范围和限制，使用已有资料继续，不假称完成参考研究。方向选择可按已有授权自行推进，不为了常规选择反复要求用户确认。

## 生成前的主题方案

在项目私有目录形成 theme-plan.md。site-plan.md 管页面和字段，theme-plan.md 管它们的具体视觉表达。方案要能指导另一个模型实施，不能只写“高级、简约、大气”。

| 内容 | 需要落地的决定 |
|---|---|
| 业务与视觉意图 | 主要访客、主要行动、品牌气质；本项目希望建立的观感及其业务依据 |
| 参考与取舍 | 实际网址、查看日期和范围；具体借鉴什么、舍弃什么、怎样转成自己的设计 |
| 视觉识别 | 3—5 个可实现的设计特征，例如标题比例、图片构图、线条或版面关系；避免的模板习惯 |
| 色彩体系 | 页面底色、内容表面、正文、次级文字、品牌色、强调色及边框的实际色值；大面积使用比例和区块切换理由 |
| 排版体系 | 中文与西文字体及回退、标题与正文比例、字重、行高、行宽、断行和段落间距 |
| 首页区块草图 | 逐段写内容任务、构图、素材、视觉主次、与上一段的变化、行动入口；不是只列模块名称 |
| 图像方案 | 原图、用途、完整展示或裁切、焦点与安全范围、桌面/手机比例；同组素材的明暗、背景、主体尺度与处理边界，必要替代方案和素材缺口 |
| 组件与页面 | 导航、按钮、链接、列表、参数、FAQ、表单与状态；首页及各内页怎样共享视觉规则 |
| 动效方案 | 对象、触发条件、起止状态、节奏、作用；手机、减少动态效果和脚本失效时的表现 |
| 资源预算 | 与 site-plan.md 对齐首屏图片、字体、CSS/JS 的加载安排和体积预算；记录维持视觉质量的压缩、变体与回退选择 |
| 实现与验收 | 样式和交互入口、代表页面、要查看的视口与滚动状态、实际结果和待处理项 |

已有明确偏好就落实。进入制作后先完成首页与代表性详情的桌面、手机版本，实际查看并修正构图、素材和交互，再将成熟的规则展开到全站。用户要求先看方案或不运行时停在相应阶段。方案文字、视觉稿、静态页面和接入 PHP 的网站分别报告，不把其中一种当成另一种。

### 用局部视觉样稿选择方向

方向不清且任务包含视觉制作时，用企业已确认的真实标题、Logo 和可用图片制作两个局部样稿，可采用静态 HTML/CSS 或其他可实际查看的视觉稿。每个覆盖首屏及一到两个有真实内容的后续区块，展示桌面与手机的构图；围绕同一业务重点比较标题比例、图像关系、色彩面积和区块衔接，不各做一套完整网站，也不靠占位口号或借来的企业图片撑效果。

已有明确品牌规范、偏好或获认可的方向时，直接深化一个样稿。采用哪个方向及理由、样稿位置和未验证内容合并进 theme-plan.md，常规选择按已有授权完成。样稿可继续完善为正式代表页面，减少重复实现；视觉稿中的字体、图片和效果须能在项目环境中实现。

仅要求文字方案时记录样稿待制作；不运行时不启动预览服务，缺少视觉工具时如实说明尚未实看。静态样稿不证明动效、后台保存或 PHP 集成已通过，这些进入后续实际验收。

## 成功经验的迁移

制作前同时读取 design-quality.md。用其企业判断、素材与构图、区块节奏、内页分工及实际预览方法控制质量；新企业重新确定视觉方向，不能只给上一个成功站换 Logo 和颜色。

## 美感落实到具体设计

### 色彩和背景

- 先用品牌与图片建立色彩关系，再确定页面底色。纯白、暖白、深色或饱和色都可选，没有通用的“高级配色”。不因没有想法就默认米白加棕色、奶油绿、蓝紫渐变或黑金。
- 背景、图片、文字和按钮放在同一屏判断。图片本身偏黄或信息杂时，不再用同色浑浊底色包住全页；可采用清晰的中性色、留白或独立图像区建立边界。色彩选择应解释为何适合这家企业。
- 用明度、面积和少量强调色安排焦点，保留足够文字对比。区块变色服务于内容分段与节奏，不给每段套一种浅色；深色首屏也不能把所有内容都压在灰字里。

### 字体和版面比例

- 用真实中文标题试排，确定标题、正文、数字、辅助信息的大小关系；大标题要有构图作用，不是统一放大字号。控制断行、标点悬空、孤字和过窄长句；禁止用装饰英文填充不需要的双语标签。
- 正文字号、行距、行宽以实际阅读为准。采用可用的中文字体和稳定回退；自托管字体须有授权并控制加载体积，不依赖不可访问的远程字体维持布局。
- 统一栅格、对齐基线和间距等级，允许不对称构图与宽窄变化。留白用于区分内容，不用大段空白掩盖资料不足。按钮、圆角、线条和阴影要有统一尺度，不把每个元素都做成厚阴影圆角盒子。

### 首屏和浏览节奏

- 首屏及紧接的核心介绍尽早交代品牌或主体、提供什么、服务谁，以及有资料支撑的具体特点；有清楚的视觉中心和下一步，不能只放抽象口号。核心信息以可读 HTML 呈现，不只放在图片中；不设“前 200 字”抓取门槛，也不把所有企业信息挤进主视觉。可以用完整摄影、产品细节、文字主导构图或有实际内容的分屏，选择取决于企业与素材。
- 资料充分时，让首页有从业务认识、能力或产品细节、真实证据到行动入口的深度；也可按访客任务采用其他顺序。不要只有简介、三张优势卡和联系表单，也不要为凑层次硬加无依据的数字、时间线、客户 Logo 和案例。
- 通过全宽与限宽、大图与细节、叙事与比较、疏与密建立节奏。按内容选择主次图组、产品展开、参数比较、项目过程、真实场景、文章索引等表达。连续几个区块若只是同样的标题加等宽卡片，应重做层次，而非继续换图标。
- 设计一个与企业有关的视觉记忆点，例如产品形态贯穿的线条、真实工艺细节、人物与场景的叙事关系或独特的版面比例。不要用通用粒子、发光球、浮动数字、星号和无意义徽章充当品牌特色。
- “复杂”不是模块越多越好。页面深度来自有效信息和设计关系，精简页面也应有完整的主次、素材和细节，不能退化为通用占位模板。

### 贯穿内页

首页、列表、详情、案例、文章、企业介绍与联系页共享色彩、字体、导航、按钮和图像规则，布局按任务调整。产品详情展开用途与条件，案例讲过程与证据，文章保证阅读，联系页提供真实入口；不要首页做完后，内页全部退回同一个白底文字卡。

- 产品详情突出用途、形式、条件和下一步；服务解释双方职责及确认环节；方案解释场景问题与适用组合，不在三个栏目反复复制同一段流程。只补有材料依据的信息。
- FAQ 独立页回答只输出一次，避免简介和正文原样重复；列表使用紧凑问题行和按需展开的答案。桌面与手机导航从同一菜单配置生成，共享可见性和当前项逻辑，删除页面不在手机菜单残留。增加入口后复查中间宽度，必要时提前切换折叠菜单，不能挤压 Logo 和主要操作。重要问答应在主导航、合作导航或明确的常用入口可发现，不能只能靠页脚寻找。
- 文章列表以标题、摘要、日期与阅读链接形成可扫描的行列表，封面只有提供识别价值时才展示，不套用产品的大图卡片。缺少封面的内容不输出空图片容器。文章使用适宜行宽的单栏阅读布局，署名和时间弱于标题；封面按内容安排，不统一套用产品的左右大图模板。企业介绍按叙事安排，避免各类页面只有标题不同。短文若没有超出 FAQ 的信息，应合并或充实实际有依据的内容，不凑栏目。
- 大幅合作引导可用于首页；详情采用紧凑的下一步链接，合作页与 404 不重复输出指向自身的合作引导。面包屑中的栏目能点击返回，企业页面使用实际页面名称。
- 首页每类推荐设置展示上限并保留“查看全部”，不能将所有新增内容无上限铺到首页。卡片按素材比例与主体尺度保持一致，不以固定高容器制造大量空白，也不以裁掉产品或海报文字消除空白。

通过共用样式、CSS 变量和组件维护视觉体系。后台以清晰、易编辑为主，不套前台展示动画，也不为了主题修改新增拖拽装修器。常规内容和图片继续从共用后台维护。

## 图片先选对，再适配

先查看原图和实际尺寸，再分类决定显示方式。模板不得对所有图片统一固定高度加 object-fit: cover。

将同一组产品、人物或案例图片放在一起判断明暗、色温、背景、主体尺度和清晰度。优先通过选图、排序、构图与页面背景取得协调；确需处理时，在授权范围内保存衍生文件，保留原件与对应关系。产品真实颜色、材质和结构，以及证书文字、印章和标识不能为统一观感而改变；不要给全站图片套同一滤镜。无法自然统一的素材可按用途分组或换布局，照片与证书也不强行使用同一种比例。

| 素材 | 默认处理与裁切边界 |
|---|---|
| 场景摄影 | 可按构图裁切，但保留主要人物、动作和空间关系；逐视口确认焦点，不靠居中自动裁切决定一切 |
| 人物照 | 优先使用干净的人像原图；裁切时保护脸部、头顶、手势及与业务相关的物件，避免相邻文字遮挡人物 |
| 产品图 | 目录与规格页优先完整展示轮廓，保留一致尺度；细节特写应有明确目的，不能让主图看不清是什么产品 |
| 含文字海报、证书、流程图 | 默认按原比例完整展示，使用自然高度或 contain；不得裁掉标题、姓名、标识、印章与必要说明，手机端必要时提供可放大查看 |
| Logo 与合作标识 | 使用 contain、合适安全边距和清晰尺寸；核对透明底、背景适配与边缘，不拉伸、不切角、不自行改色或去掉组成部分，按下方 Logo 专项规则处理 |

只有海报但想用人物时，先寻找授权的无字原图。确需取海报中的人物，必须检查裁切结果确实无残缺广告字、无被截断的主体且符合使用许可；做不到就换图、完整展示为资料或重新安排版式。不能把海报放大裁掉一半后，加“原图含营销文案”“此处裁切人物”来解释。

访客图注只描述有助理解的真实内容，如人物身份、项目、场景或必要署名；不输出素材处理、核验过程或“不作本页正文”等制作说明。alt 是可访问的内容替代，也不承载这些内部说明。内部说明归入素材清单和后台，详见 content-model.md。

实现时按素材确定 aspect-ratio、自然高度、object-fit 与 object-position。必要时通过 picture 提供桌面与手机的不同构图，srcset/sizes 提供合适分辨率；不能把手机版直接缩小桌面画面。为图片声明尺寸或预留比例，优先加载首屏关键图片，其余合理延后。图片与旁边文字须有独立边界、min-width 与合理重排，防止图文叠压、挤出容器或被 overflow 裁掉。

所有主视觉、产品主体和含字素材都要在桌面和手机实际查看。源码里写了正确属性、图片成功加载或说明“已经裁切”，都不等于视觉处理合格。素材不够时优先用排版和真实现有图片重新构图；不能用虚构现场、客户、证书或产品补画面。

确需解释概念或流程时，可在具备相应工具与授权的条件下制作示意图或抽象视觉，并在素材记录中注明性质。容易被误认成实拍或真实成果的图，应在使用处明确其示意用途；不得生成工厂、实验室、团队或客户现场来证明企业实力。关键事实和条件仍提供可读文字，图像质量与访客体验同样属于设计要求，不以“AI 看不到图片”为由削减展示质量。

### Logo 与背景的适配

Logo 是品牌标识，不直接套用普通图片卡片样式。先查看原图，再检查实际页面；区分图片像素中的底色或边框、Logo 本身的图形边界，以及容器或链接添加的 border、background、shadow 等样式。

1. **确认素材性质。** 检查文件的真实透明通道、边缘像素、画布留白和有效标识范围。PNG 后缀不代表透明，截图里的棋盘格也不代表透明；白底、近白底、拍照纸面、压缩杂边和透明区域要分清。不要把拍摄招牌或印刷品的照片直接当作数字 Logo。
2. **优先选对原件。** 从授权素材中优先寻找可安全使用的 SVG、透明 PNG/WebP，以及品牌提供的深浅背景版本。按照真实背景选择版本，保留商标图形、字标、颜色和必要安全距离；不得为了适配重新生成、描绘或随意反色。
3. **解决原图底色与杂边。** 只有带底色的文件时，先查是否有合适原件；确需抠底、裁边或整理画布时，在不改变品牌标识的前提下生成衍生文件并保留原件。检查细字、白色图形、镂空和半透明边缘，不能把标识内部的白色一并删掉。放到实际浅色和深色背景查看，确认没有白晕、锯齿或残留底板。仅改文件后缀、设置 contain 或 border: 0 都不能去除原图中的底色与线框。
4. **让背景形成整体。** Logo 与所在区域不应出现无设计意图的近白色色差或突兀矩形色块。无法得到透明版本且品牌要求保留底色时，可设计与该底色一致的连续品牌区域，并与页头构图协调；不能随手加白色卡片、细边框、圆角或阴影遮掩色差，也不为一张不合适素材随意改变整站主题。素材仍不合用时记录私有缺口，不把缺陷当作已解决。
5. **清理页面附加样式。** Logo 图片和包裹它的链接默认不继承内容图片的边框、圆角、阴影和卡片背景；检查普通、悬停及吸顶状态中的样式来源。Logo 原设计中的外框或底板应保留。键盘 focus-visible 是必要操作反馈，不能当成多余边框一并删除。
6. **保持色彩、比例与大小。** 不用 mix-blend-mode、降低整体不透明度或反色滤镜自动“去白底”，这些处理可能改变品牌颜色与边缘。保持宽高比并完整显示，按有效标识尺寸而非整张图片画布判断视觉大小；过多留白可在许可范围整理，但不得侵占品牌安全距离、切掉字标或强行拉伸。深浅背景版本切换时预留稳定占位，避免导航跳动。
7. **覆盖实际使用状态。** 查看桌面与手机的页头、页脚、菜单展开、滚动吸顶，以及项目确实启用的透明导航或深浅背景状态。逐处核对版本、对比度、比例、清晰度、对齐及背景边界；没有该状态就不凭空增加功能。后台换 Logo 后，同样检查各处引用与适配，不能只确认上传成功。

在私有素材记录中保留原件、衍生文件、透明度与适用背景等信息，前台不输出抠图、换底或裁边说明。验收对照品牌原件与页面截图，出现非设计的底板色差、多余线框、白边、颜色改变或标识不完整时须修正。

## 滚动交互与动效

品牌展示首页应设计并实现一处有内容意义的滚动展示或浏览交互，并配合必要的按钮、导航和展开反馈。可选滚动章节、固定图像配逐段说明、工艺步骤变化、用户控制的横向作品浏览或局部图像进入；根据业务选用，不全部叠加。资料型站点或设备限制不适合展示性动效时，说明取舍并用清晰的浏览反馈与静态构图保证质量。

- 在 theme-plan.md 写清动效展示什么、为何需要、何时触发、怎样结束。不能仅写“加滚动动画”，也不能只给每个区块复制同样的淡入，便宣称完成交互设计。
- 以少量关键场景为主。悬停和点击反馈可从 120—220ms、内容进入可从 300—600ms 试调，作为起点而非所有品牌的固定值。首屏标题、主营业务和主要按钮立即可读，不要让访客等待逐字动画或多秒进场。
- 页面保持正常滚动与原生导航，不劫持滚轮、禁止触摸滚动或让访客滚多屏才能看一句话。固定展示区有明确结束点；手机通常改为正常纵向流，横向内容保留可发现、可点击的控制方式。
- 优先采用 CSS、IntersectionObserver 或能力检测后的滚动时间轴；复杂场景确有需要再选择轻量交互依赖并核对许可和性能。H5＋原生 PHP 不排斥有设计目的的 JavaScript，不为动画改换技术栈。
- 优先动画 transform 与 opacity，避免频繁改变布局尺寸。视频有静态封面与暂停能力，默认静音且不妨碍阅读；不把巨大视频、连续帧、3D 或背景特效当成高级感的必需品。
- 支持 prefers-reduced-motion；在减少动态效果、脚本未加载、接口不支持和窄屏状态下，正文仍完整可读、入口仍可操作。渐进增强不能先让全部正文透明后等脚本来救；装饰动画可停，业务内容不可消失。

静态截图只能检查静态外观。授权运行时实际向下和向上滚动、操作导航与交互，观察初始、中间、结束状态，以及减少动态效果和手机状态。动画导致卡顿、文字被挡、布局跳动或入口失效时先修复，不以“动效已加”作为通过。

## 内容与技术底线

- 访客页面使用正式业务语言，教学、测试、资料缺口、设计理由与开发备注不出现在前台。必要的法律、隐私和产品提示保留；样例隔离及正式发布检查遵循 content-model.md。
- 每页说明具体业务、适用条件、可核依据和下一步。真实联系方式从共用数据读取；缺失时省略相应入口，不放假电话、假二维码或假提交成功。
- 产品/服务、方案、案例、FAQ 与文章按真实关系连接。导航与公开目录仅显示已发布内容；没有内容的栏目不留空壳。手册、视频作补充，不替代关键 HTML 正文。
- PHP 输出完整可读的主要正文和链接。动效、图片或 Canvas 不能成为业务信息的唯一载体；文章时间、canonical、响应状态及 JSON-LD 与实际页面一致。
- 审美和性能同时检查：控制图片与字体体积、保留图片尺寸、按需加载非关键资源。首屏主图不延迟加载，字体有本地回退；具体资源与测量规则见 deployment.md。首屏质量不能靠等待大量脚本和视频达成，性能达标也不能替代视觉完成度。

## 视觉验收与修正

对照 theme-plan.md 与实际参考，查看首页、列表、代表性详情、文章、联系及启用的其他模板。至少覆盖 390px 手机、768px 中间宽度和 1440px 桌面；必要时补充更窄手机或大屏。

每项记录实际页面、视口、观察和证据，用“通过／需修正／未检查”表达，不给没有依据的高级感分数：

| 维度 | 通过判断 | 必须返工的迹象 |
|---|---|---|
| 品牌与审美 | 主视觉、颜色、字体和图片共同表达该企业，能说明与通用模板的差别 | 只换 Logo、口号和颜色；默认配色与素材互相冲突 |
| 首屏构图 | 业务清楚，主体与标题有主次，动作入口可辨，实际中文字排版完整 | 空泛巨字、孤字断行、装饰淹没主体、主图靠裁切凑尺寸 |
| 内容与节奏 | 连续区块有任务和主次变化，详情有相应深度，内容可核 | 三张优势卡反复堆叠、空区块、伪造数字、极简到不能理解业务 |
| 图像 | 主体、必要文字和标识完整，色调及清晰度适合页面，图文边界稳定；Logo 与背景协调且边缘干净 | 切脸、切字、拉伸、海报残字、图片被文字盖住、破图；Logo 有非设计底板色差、杂边或额外边框 |
| 动态体验 | 滚动展示有意义、状态连续，手机和减少动态效果下可用 | 所有模块同一淡入、滚动卡住、动画遮正文、关闭脚本后空白 |
| 全站一致性 | 内页保持同一设计语言，导航、表单、焦点、错误状态与移动重排完整 | 首页精修、内页默认；每页配色字号不一致 |
| 对外完成度 | 页面只有访客需要的内容，入口真实可用 | 教学横幅、资料处理备注、占位联系方式、假提交成功 |

图片或文字截断、图文重叠、虚假入口、内部提示外露、不可读动效属于直接失败项，不能用其他评分抵消。只有 HTTP 正常、无横向溢出或完成配色表，不算视觉通过。

首页与代表性详情未达到所选方向时，先修正代表页面再批量扩展。全站完成后再复查跨页面一致性。Skill 评测由至少两位未参与制作的评审人分别评价品牌辨识、信息疏密、图文质量、全站一致和操作体验，与参考并排比较并指出具体区块；调整后同视口复查。普通建站按客户约定的审阅人和节点执行，不要求每次另找两位评审人。Agent 自评不能冒充真人认可，未开展的评议记录未执行。

## 可复用的参考观察

以下是研究入口和观察方法，不是默认模板。网页会变化，项目使用时重新查看并选取贴合该企业的参考。

- [Apple iPhone](https://www.apple.com/iphone/)：观察产品图的视觉主次、标题比例、选择与比较的层级；不照搬产品事实、素材、巨大页面体积或电商功能。
- [Linear](https://linear.app/)：观察产品画面与文字的关系、细线和间距的一致性；借鉴设计纪律，不把它的深色软件界面推广到所有企业。
- [Muuto](https://www.muuto.com/)：观察场景摄影、文字尺度、不对称版面和故事区块的配合；品牌色及英文排版不能原样搬到中文站。
- [DJI Osmo Pocket 3](https://www.dji.com/cn/osmo-pocket-3)：观察中文产品首屏、主体特写和分段内容；资源与交互开销须按当前项目重新判断。
