# 项目部署与维护规范

根据企业实际环境生成部署文件与可执行说明。本文件规定交付要求，具体配置、路径和命令应与当次生成的项目一致；实际部署情况记录在项目交付材料中。

## 顾问的部署选择与责任

先核对项目阶段、目标访问地区、已有域名与主机、预算、维护人员及权限。新站选择环境；旧站先判断已有环境与改动兼容性，多站分别记录，不因梳理任务自动采购或部署。

| 选项 | 核对事项 | 交付判断 |
|---|---|---|
| 复用现有 PHP 主机 | 受支持版本和扩展、数据库、Web 根目录、媒体、备份、日志与任务能力 | 满足时优先复用；列实际缺口及替代路径 |
| PHP 托管主机 | 路由、HTTPS、存储、数据库权限、日志、定时任务及服务商限制 | 说明哪些由服务商提供、哪些需手动或维护电脑处理 |
| 自行管理的服务器 | 系统和服务维护、访问控制、监控备份、人员能力与持续费用 | 有实际管理需求和维护责任时选用，不预设所有企业都需要 |
| 可选 GEOInflow | 独立服务资源、数据库、账号与日志权限 | 明确选用后另核对，不作为默认建站前置条件 |

给出建议方案、选择理由、所需配置或容量依据、费用项、缺少条件和可执行下一步。资源规格按内容、媒体、预计负载及实际验证选择；价格按当次官方报价与使用范围核对，未确定金额标待定。域名与目标地区上线前置条件按实际要求检查，不把历史报价或环境快照当成当前结论。

顾问组织范围与验收，企业确认事实并提供获准资源和账号，部署人员执行配置，后续维护人负责更新、备份与故障。角色可由同一人承担，但需明确交接。凭据通过安全渠道单独传递；不把一次建站扩展为无限期托管、代运营或自动续费承诺。

方案、部署文件、本地运行、预发布、正式上线分别记录。缺正式主机时继续已授权的代码及本地工作；只要求诊断或资料梳理时不启动部署。线上完成依据来自真实目标上的访问、配置与实际操作，不由本地检查替代。

## 官网环境

官网目标为 PHP 8.3+、MySQL 8.0+，使用 PDO MySQL、Fileinfo、Session。实施前选择仍受维护且环境支持的具体版本，记录实际版本；辅助工具有额外扩展时一并说明。

先实际读取 PHP 版本和扩展，并在独立测试库核对连接权限。Windows 环境如遇中文路径加载失败，使用授权范围内稳定、共享的 ASCII 运行目录；临时目录须确认跨进程可访问。数据库明确指定自身数据目录和监听地址，不连接或初始化已有客户库。环境问题单独记录，不替换为其他数据库来冒充 MySQL 验收。

基础路径为普通 PHP 主机，不要求 Node、PHP 框架或第三方 CMS。需要 Docker 时再生成对应构建、服务、持久卷和配置示例，不把容器当成所有企业的必需条件。

## 新建官网需要生成并说明的步骤

本节适用于新站初始化。旧站只执行约定修改所需的迁移、配置与复查，保留现有数据库、账号和无关功能；多站仅梳理信息时不执行安装。

1. 创建独立项目目录，生成完整源码、建表 SQL、配置示例、初始化和内容工具；不覆盖现有站点。
2. 创建 UTF-8 的空 MySQL 库，在明确的新库执行建表。部署账号与网站运行账号分开，运行账号仅保留必要读写权限。
3. 将真实配置放在 public 外，生成随机密钥并安全传入数据库凭据。交付包中只含无真实凭据的配置示例。
4. 把 Web 根目录指向 public，按真实服务器生成 Apache 或 Nginx 路由配置。PHP-FPM 地址、路径及端口使用实际环境值。
5. 给服务账号分配必要的媒体和会话写权限，代码及配置限制写入。上传目录不作为可执行 PHP 目录。
6. 使用生成的私有初始化工具创建管理员。不提供公开安装入口；初始管理员为 admin / 123456，哈希保存，通过后台账号设置修改。初始化不得覆盖已有账号密码；正式上线交接提醒更换初始密码。数据库和 SMTP 凭据不写进公开源码、日志或报告。
7. 使用项目内容工具预览并导入确认数据；来源原件、计划和导出存放在公开目录之外。
8. 配置 HTTPS、可信反向代理、实际缓存策略和失效权限，按 native-php.md 排除私有请求。设置可信站点根地址，避免生成 localhost、测试域名或任意 Host 头拼出的公开网址。教学或预发布环境仅本机可访问或经过鉴权，并禁止索引；不能把 noindex 当访问控制，也不通过前台教学横幅承担隔离。
9. 在授权范围启动与验收，记录可访问地址、已测环境、失败步骤及处理结果。
10. 正式发布前核实或移除教学样例、未确认事实及假入口，检查 demo 状态和访客页面内容；不能仅移除说明或改标志就公开样例。按任务范围发布和交接，区分本地运行、演示部署与正式上线。

网站项目的 README 必须提供真实生成文件对应的复制即可调整使用的命令，说明工作目录、先后顺序、参数、成功现象和失败排查。不得把示意命令写成已执行结果。

## 页面与资源性能

在 site-plan.md 结合实际图片、字体、交互和目标终端，确定每类代表页的首屏图片、字体、CSS/JS、总传输体积及请求数预算，填写数值、单位与理由；预算是项目目标，不写成通用排名门槛。主题效果与性能分别通过，不以压缩到失真、删除必要内容或取消主要交互换分数。

| 部分 | 生成与配置要求 | 核对方式 |
|---|---|---|
| HTML | PHP 直接输出核心正文、产品条件、FAQ 答案和真实链接；监测不可用不阻断官网请求 | 原始响应及关闭脚本时可读，不能只有骨架或图片中的文字 |
| 图片 | 生成符合显示尺寸的压缩变体与回退，按需使用 srcset/sizes；声明宽高或比例，保留原件与授权信息 | 对照原图、实际清晰度、加载尺寸和布局位移；Logo 透明度与边缘按 design.md 检查 |
| 首屏 | 关键主图直接可发现，不设置 lazy；确有收益时为主要 LCP 图片设置高优先级，避免给所有图片预加载 | 实际网络瀑布及 LCP 元素，确认没有重复请求或等待脚本后才加载 |
| 下方资源 | 非首屏图片按需延迟加载；视频先有合适封面，用户播放或接近可视区后加载所需资源 | 首屏不下载整页大图与整段视频，滚动至对应内容时正常呈现 |
| CSS / JavaScript | 共用样式复用，页面专用脚本按需加载；非关键脚本延后，避免全站装入大型动效库与长任务 | 资源清单、菜单/滚动/表单操作、禁用脚本和减少动态效果下的可用性 |
| 字体 | 优先清晰可用的本地系统回退；有许可的自托管字体控制字重和字集，合适使用 font-display | 字体请求失败时仍可读，避免全量中文字体与字体切换导致的大幅跳动 |
| 传输 | 按服务器支持启用文本压缩，静态资源采用版本化 URL；图片不因传输压缩重复处理 | 实际响应头、传输体积及资源更新回读 |

图片衍生处理所需的 GD、Imagick 或构建工具按实际实现列为依赖；无法生成时先记录限制，不声称已优化。第三方资源在目标地区可能不可用时优先采用有许可的本地资源与回退，不让外部字体、统计或监测成为正文的必需前置请求。

## PHP、MySQL 与缓存部署

按真实查询选择索引：稳定 key/slug 的唯一性、公开范围与类型/分类的列表过滤排序、关联表查找。保存关键 SQL 及 EXPLAIN 依据，限制列表条数并分页，批量读取关联数据，避免每张卡片各查一次和同请求内重复加载企业信息。不要机械给所有字段加索引；表结构和迁移与代码一起交付。

环境支持时启用 OPcache，核对实际 Web 服务进程的扩展和配置，不能用 CLI 状态代替 PHP-FPM/Apache 状态。说明代码更新时的生效/重载方式，不设置公开重置入口；共享主机不能控制时记录环境限制。

按 native-php.md 实现选定的公开页面缓存，记录目录/服务、权限、TTL、容量清理、版本切换、手动重试、回滚及失效失败后的处理。实际观察 HIT、MISS、BYPASS，不能用响应快推断命中。选择 CDN 前比较目标地区访问、费用、日志来源和缓存清理能力；未使用 CDN 写明不适用，不假称完成边缘验证。

恢复数据库、更新模板或更换域名后同步处理页面缓存、目录、静态资源版本及 canonical。私有内容隔离检查覆盖应用、服务器和实际启用的 CDN。缓存生成物不作为事实源，也不放入最终交付压缩包。

## SEO / GEO 输出与发布

在 site-plan.md 建立“目标问题/搜索意图—页面类型—数据字段—实际输出—更新触发—验证地址”映射，生成时落到 PHP 模板和共用内容服务中。抓取、规范网址、结构化与更新是 SEO/GEO 共用基础；搜索展示与 AI 回答分别观察，不生成两套相互漂移的内容。

| 项目 | 实施规则 |
|---|---|
| 标题与摘要 | 每个独立页面根据本页业务生成有区别的 title 和 description；默认按标题和简介生成，确需后台维护时用折叠的“搜索展示设置”及普通中文字段，避免全站复制企业简介或塞入关键词 |
| 规范网址 | 每页最多一个 canonical，使用可信配置的绝对公开 URL，与 sitemap 和内链一致；默认规范页指向自身，分页和筛选按实际内容决定，不能全部指向首页 |
| 可发现链接 | 导航、栏目、详情及关联使用可请求的 a href；不只通过按钮脚本跳转，不出现未公开内容链接、空白栏目或无依据的推荐 |
| 索引控制 | 生产与预览配置分开；公开页面按范围允许索引，登录/后台/预览保持鉴权与 noindex。robots 管抓取，不承担保密，也不把 Disallow 当删除索引；需要读取 noindex 的公开 URL 不同时阻断抓取 |
| 状态与迁移 | 正常页返回 200，不存在或删除页使用恰当的 404/410，不输出旧正文；真实迁移采用 301/308 至对应新页，避免循环、多跳和全部跳首页的软 404 |
| sitemap 与目录 | sitemap 只列应公开索引的有效规范页；监测目录按 content-model.md 导出，范围有差异时记录依据。真实内容变化才更新 lastmod，不把每次请求或缓存重建时间当内容更新时间；保存、删除和迁移同步维护 |
| 结构化信息 | 按下方类型与关系映射生成页面内 JSON-LD；只填实际可见、有依据的名称、地址、作者、日期、问答与参数，不凑造价格、评分、评价、资质或效果 |

### Schema 类型关系与校验

Schema.org 定义类型和属性，JSON-LD 是本方案使用的表达格式。在实际页面输出 `<script type="application/ld+json">`，由共用内容服务生成并安全编码；只交付独立 JSON 文件或在页面放下载链接，不算页面已部署结构化数据。生成时按对应 Schema.org 类型及目标平台当前文档核对属性的适用范围，不将所有字段塞入所有类型。

| 对象 | 类型与主要字段 | 关系及使用条件 |
|---|---|---|
| 企业与门店 | Organization 或适用子类型；name、url、logo、公开 contactPoint/address；有真实本地经营地点时选择适用的 LocalBusiness 子类型 | 同一实体使用稳定 @id；不同法人、分支与门店分别建标识，parentOrganization 等关系需有事实依据，不把品牌名、法人名、门店名混为一项 |
| 网站与页面 | WebSite、WebPage；name、url、inLanguage | WebSite 的 publisher 关联实际发布主体；WebPage 的 isPartOf 指向网站，mainEntity 指向本页主要对象，breadcrumb 指向适用的导航节点 |
| 产品 | Product；name、description、image，按真实资料使用 model、sku、additionalProperty 等 | brand/manufacturer 按事实关联；offers、价格、币种和供应情况只有实际公开时才输出；不把不存在的商家报价或评价作为必填补齐 |
| 服务 | Service；name、description、serviceType、实际 areaServed | provider 指向真实提供者；不要把服务统一当 Product，也不为了字段完整捏造价格或服务地区 |
| 文章与案例 | Article 或合适的 CreativeWork 子类型；headline、实际 author/publisher、datePublished/dateModified、image | mainEntityOfPage 关联页面；about 关联实际主题。自有案例不伪装独立新闻，作者与时间未确认时不编造 |
| 导航 | BreadcrumbList、ListItem；position、name、item | 对应实际栏目层级与有效链接，不用虚构栏目或链接凑路径 |
| 问答 | FAQPage、Question、Answer；mainEntity、name、acceptedAnswer/text | 页面确有可见问答时按用途选用；支持用户展开阅读的内容须实际存在。Schema.org 类型有效与平台特殊展示支持分别判断 |

一项服务的关系可以是 `WebPage.mainEntity → Service`、`Service.provider → Organization`，页面与企业通过稳定的绝对 URL 加片段标识，例如站点根地址加 `#organization`。已有有效实体 ID 优先沿用；用稳定记录标识维护同一实体，更名不随意重建，域名迁移明确映射。简单页面可用单对象或嵌套对象，多实体时可用 @graph，不为每页强行凑节点。

sameAs 仅指已核实的同一身份页面，如真实官方账号或对应实体资料；普通报道、客户案例和证明资料使用正文来源链接或适用的 citation 等属性，不靠堆 sameAs 制造权威。结构化数据不输出内部来源路径、核验过程、私有联系方式或未公开业务。

依次检查：JSON 能解析；类型和属性适用；本地节点无冲突且引用可解析；字段与可见正文及确认资料一致；匿名响应确有标记。可用 Schema Markup Validator 检查词汇与结构；Google Rich Results Test 只检查其支持的富结果类型，不以“未检出富结果”判定 Service 等标记无效，也不以通过校验当作已展示或引用。保存、更名、删除、事实修正及恢复后同步回读正文与 JSON-LD。

Google 已停止 FAQ 富结果展示；保留问答内容的理由应是帮助访客解决问题，采用 FAQPage 则依据实际语义或目标系统用途。不要沿用旧教程把普通企业 FAQ 展示资格当成卖点。其他类型的富结果资格按相应平台当前支持核对。

类型与校验依据：[Schema.org Organization](https://schema.org/Organization)、[WebPage](https://schema.org/WebPage)、[Product](https://schema.org/Product)、[Service](https://schema.org/Service)、[Article](https://schema.org/Article)、[BreadcrumbList](https://schema.org/BreadcrumbList)、[FAQPage](https://schema.org/FAQPage)、[Schema Markup Validator](https://validator.schema.org/)、[Google 结构化数据说明](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data)、[Google 组织标记](https://developers.google.com/search/docs/appearance/structured-data/organization)、[FAQ 展示支持说明](https://developers.google.com/search/updates#may-2026)。

### 目标平台、发现与更新

上线前从匿名响应检查 robots、meta robots、X-Robots-Tag、canonical、链接、sitemap 和 JSON-LD，尤其排除遗留测试域名、正式页误设 noindex、私有页错误开放及删除页仍返回 200。提交站点地图或搜索平台验证仅在对应授权和账号条件下执行，未提交如实记录。

按客户市场选择实际目标平台，核对其搜索发现、内容控制及账号开放能力。国内项目同时参考百度的网页标题、正文和时间信息规范；不能假设百度、豆包、千问、DeepSeek 与 Google/Bing 使用同一套 Schema 展示、提交接口或抓取身份规则。无公开官方依据的能力记为待核实，公开搜索规则不直接外推到同品牌全部 AI 产品。涉及信源权威分级时记录具体产品、规则来源和适用范围，不把某个搜索 API 的分级当成消费者端固定引用排名；不按 To B／To C 或企业规模直接断言官网能否被引用，实际表现另用目标问题的回答观察。

分别判断搜索抓取、用户请求和训练用途，不为 GEO 一律放开所有机器人。以 OpenAI 为例，OAI-SearchBot 用于搜索，GPTBot 涉及训练，ChatGPT-User 是用户触发访问，三者不能相互替代。按实际发布目标配置，并核对可信 IP、CDN/WAF 与服务器规则；模拟 UA 请求只检查当前响应，官方实际来访还需真实日志。Google 的 AI 搜索另查当前 Search Console 控制，Bing 的训练/回答依据使用偏好另查其现行说明，不只检查 robots.txt。

对已授权、支持且需要及时通知的引擎，可选接入 IndexNow：验证自有站点后，仅通知真实新增、修改、删除的本站公开 URL；删除项按历史公开地址通知，不能只从现存 sitemap 取变更。密钥按协议配置，响应与失败重试留在私有记录；不发送预览、后台或其他企业网址。正常接收仅证明通知送达，继续检查抓取与索引。未实施时给出建议和接入条件，不标记为内置自动提交功能。

llms.txt 仅在有明确使用方、合同约定或小范围实验目的时采用，包含允许公开的简介与有效页面链接，随内容维护；不输出知识库原件或私有记录。Google 明确不依靠该文件改善搜索可见性，其他服务是否使用须另查依据。SEO/GEO 的工程目标是提供可访问、可理解、一致且有依据的官方内容，实际索引、引用和业务结果按后续观察判断。

平台依据：[Google AI 搜索优化指南](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)、[Bing 网站指南](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a)、[百度内页基础信息规范](https://ziyuan.baidu.com/college/courseinfo?id=3390&page=3)、[OpenAI 爬虫用途](https://developers.openai.com/api/docs/bots)、[Google AI 搜索控制](https://support.google.com/webmasters/answer/16908024)、[Bing AI 使用偏好](https://www.bing.com/webmasters/help/new-ai-preferences-2t1cc16d)、[IndexNow 协议](https://www.indexnow.org/documentation)。

### SEO 与 GEO 效果观察

在现有页面方案或交接记录中，关联目标问题/查询意图、页面 URL、确认事实、主要改动、实际发布时间、预期观察点及负责方，不另建无用途的技术后台栏目。有已有诊断或题目就复用；缺少基线时提出采集安排，不能补造“优化前”回答。实际平台测评、付费服务与持续跟踪按项目约定执行，建站任务不自动扩大为长期运营。

| 层次 | 观察项 | 证据与判断 |
|---|---|---|
| 工程实现 | 问题覆盖、事实与 Schema 一致、链接与联系方式、手机和访问体验 | 实际页面及检查结果；未部署只记录本地阶段 |
| 抓取与索引 | 重要页访问、错误、搜索平台索引状态 | 内置请求记录及站长工具 URL 检查；UA 声明、IP 匹配与已索引分列 |
| SEO 表现 | 查询、展示、点击、点击率与重要页变化 | 目标平台当前可用报表，注明时间、设备及范围；站内 PV 不能冒充搜索展示 |
| GEO 回答 | 品牌提及、事实准确性、官网引用与具体来源 URL | 目标平台原题、完整回答及来源；Bing AI Performance 可补充其支持场景的引用数据，不代替逐题事实核对 |
| 业务承接 | AI 引荐浏览、联系/下载点击、真实咨询及成交 | 网站报表与企业业务记录按可追踪范围关联；未知来源单列，不将点击计作咨询 |

复测保留原题文、平台/端、模式、会话条件、轮次与时间；前后共同题和可比条件内分别计算提及、事实正确、官网引用等指标，明确样本单位、分母与缺失。新增题、失败样本和条件变化单列，引用其他网站不当作官网引用。保留完整回答与引用页，避免仅记截图中的某个品牌词。

Google Search Console 的 Web 汇总包含其 AI 搜索功能数据，不能把全量搜索点击标为 AI 引荐；可用时另查看 Generative AI performance report 的 AI Overviews/AI Mode 展示数据。该报表展示次数不等于点击或事实正确，样本不足可能不显示，页面、属性聚合及日期时区分别核对。Bing AI Performance 仅覆盖支持的 Microsoft/Copilot/Bing 及部分合作场景，引用次数不等于点击，grounding queries 是检索归纳词，不是用户完整原题。国内平台缺少此类报表时使用真实回答样本与网站来源记录，不凭工具名称猜测全平台覆盖。

按证据安排下一步：抓取失败先查状态和访问控制；已索引但未引用时检查问题匹配、独有信息、证据与其他信源；答案事实错核对页面及外部冲突；有访问但缺行动检查内容与入口。前后变化还可能受平台、需求及其他内容影响，不把差值直接解释为单项改动的因果效果。

观察依据：[Google AI 功能流量说明](https://developers.google.com/search/docs/appearance/ai-features)、[Google 生成式 AI 展示报告](https://support.google.com/webmasters/answer/16984139)、[Bing AI Performance 的范围与指标](https://www.bing.com/webmasters/help/ai-performance-9f8e7d6c)。

## 性能目标与测量协议

目标为 LCP≤2.5 秒、INP≤200 毫秒、CLS≤0.1。上线后以手机和桌面真实访问分别计算的第 75 百分位判断；记录工具、时间窗口、样本量及页面级/来源级范围。样本不足或无真实数据记为待观察，来源级数据不能冒充某个详情页结果。

上线前采用可重复的实验室测量：

1. 选首页及每种实际启用模板的代表 URL，例如产品或服务详情、FAQ、文章。FAQ 嵌在业务页时测其承载页面并说明；方案未启用的类型记录不适用及理由，约定应有但尚未完成或缺素材的类型仍记未测，不为凑样本造页面。
2. 固定代码/数据版本、主机与区域、设备/CPU、浏览器及工具版本、视口、网络与节流设置、登录状态、部署方式、第三方资源条件。桌面和手机分别测；本地开发服务器结果不当成正式部署结果。
3. 每个代表页、终端及选定场景至少重复 3 次，保留各次值、汇总中位数和范围，不只挑最好一次。浏览器冷/热缓存与源站页面缓存分别标注；服务缓存 MISS 后用相同 URL 测 HIT，并记录 CDN 层。清缓存只作用于授权测试项目，不清其他站点。
4. 留存 LCP、CLS、TTFB、资源传输体积与请求数、缓存状态和原始报告；缺指标留空并写原因。Lighthouse 的 TBT 作为诊断指标单列，不改名为 INP，也不以总分代替三个目标。
5. 使用能测交互的工具实际操作菜单、FAQ、表单及主要交互，记录交互序列和实验室结果；无交互样本不填 INP=0。真实访问的 INP 仍需后续现场数据。
6. 未达目标时按网络瀑布、LCP 元素、长任务和位移来源定位，修正后在相同条件复测，检查图片、字体与动效效果仍合格。报告实测范围及剩余问题，不将规则、预算或单次分数写成达标证明。

测量记录至少含：页面/模板、时间、代码与数据版本、终端及网络、工具版本、浏览器/源站/CDN 缓存状态、重复序号、各项指标及单位、资源体积、原始证据、问题及复查。具体任务见 acceptance.md；可合并进项目验收文件，不强制建立独立性能平台。

实现依据：[Web Vitals 指标与测量](https://web.dev/articles/vitals)、[LCP 资源加载](https://web.dev/articles/optimize-lcp)、[HTTP 缓存语义](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)、[PHP OPcache](https://www.php.net/manual/en/book.opcache.php)、[MySQL 索引](https://dev.mysql.com/doc/refman/8.4/en/optimization-indexes.html)、[Google 规范网址](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)、[robots.txt 的作用与限制](https://developers.google.com/search/docs/crawling-indexing/robots/intro)、[Google AI 搜索技术要求](https://developers.google.com/search/docs/appearance/ai-features)。按项目实际版本和目标平台核对，来源规则不代表本站已通过检查。

## 内置监测部署

按 native-monitor.md 复制模块、迁移 ew_ 表、生成随机密钥并完成宿主适配器。PHP 运行账号只需要所需 DML 权限，迁移账号单独使用。公开根目录必须是 public；app、config、private 和数据库备份不得通过 Web 读取。复用网站登录，不新增管理员口令。

前端脚本随网站同域交付；token/event 不缓存，管理员页面与 CSV 导出先鉴权再响应。应用采集钩子在 PHP 页面缓存返回前注册。启用反向代理时，只接受来自实际可信代理且由其覆盖的客户端 IP 头；未确认代理配置时不使用 X-Forwarded-For 认定官方来源。

执行官方 IP 更新，保留私有原文哈希与状态；配置 cron.example 的每日规则更新和超过 90 天记录清理，核对实际执行回执。PHP HTTPS 更新需要 OpenSSL、可用 CA 与 allow_url_fopen；缺少时用维护电脑上的 Python 工具更新并上传快照，不关闭证书校验。没有安装定时任务时如实记录手动维护状态；超过 7 天的快照不再产生“官方 IP 匹配”。

CDN 静态缓存命中、服务器直接拦截和静态资源请求未必经过 PHP。需要完整边缘观察时，将授权日志转换为 native-monitor.md 的 JSONL，私有导入并按来源分别看；不将同一个请求的源站与边缘记录相加冒充独立访问量。目录、时间、GET/HEAD 和响应口径按实际显示。

## 可选原版 GEOInflow

只有明确选用时，按 geoinflow.md 获取固定源码、核对环境、调用官方部署入口并验证服务与本站接入。它的运行环境、数据库、登录和备份保持独立；缺少 Docker 不影响默认内置监测交付。

## 数据与运行维护

备份数据库、上传媒体、私有配置及项目定制源码。内容 JSON 导出不能替代完整数据库、媒体和配置备份。计划备份周期、保留位置和恢复负责人，凭据单独保管。

恢复先在独立目录和数据库执行，再核对企业信息、公开内容、私有内容、图片、关联和管理员访问，不覆盖现网。容器重建不得删除客户持久数据。

备份与恢复逐项检查文件创建、写入和复制结果，并核对媒体清单与哈希；任何一步失败都返回失败并说明已完成的部分。恢复前验证目标目录可写及备份完整，安排数据库与媒体的提交、回滚或清理顺序，不因数据库操作成功就宣称全部恢复成功。验收在隔离目标模拟文件写入失败，并检查实际恢复目录中的图片可读。

应用更新先核对当前源码、数据和人工修改，再生成必要迁移与回滚方法。PHP/MySQL 与内置监测升级按实际受影响功能验证；可选 GEOInflow 单独验证。
