# 验收方法

只在本次授权范围内执行。用户明确暂不测试时，保留任务定义，不生成样站、不启动服务、不连接数据库、不运行检查脚本或模型评测。实际结果记录在对应项目的验收材料中。

## 记录方式

每项记录任务 ID、执行人、Agent 与模型、工具权限、输入材料、环境版本、步骤、预期、实际、证据位置和时间。状态使用 passed / failed / not_run / blocked；未执行不填通过。失败项保留原因、修复动作和复查结果，教学结果与真实访问分开。

每站验收以本文件中当前场景和阶段的适用项为任务表；Skill 评测另使用 evals/evals.json 的两套资料、独立评议与对照任务。栏目和页面类型以项目方案为准，下文提到产品、服务、FAQ、文章等时，仅检查实际启用项，不为验收补建空栏目。素材、页面类型或 CDN 等确不适用时记录适用性与依据；约定应有但尚未实现的功能仍为未完成，不能以“不适用”跳过。每个问题列负责人、影响范围和复查条件，由发现者复查，主制作人检查完整流程。下面的步骤与阈值均为要求，执行后才填写结果。

## 按场景确定验收对象

先核对项目简报中的顾问目的、客户问题、所选场景、交付阶段和权限。新站执行本阶段完整建站验收；旧站只诊断时验收诊断材料，实施后再检查变动及受影响链路；多站信息一致性梳理验收一致性判断和逐站建议，不要求每站重建后台或监测。

旧站诊断通过需问题对应实际页面、证据、业务影响、优先级、保留项、实施条件和验收办法；未知技术栈、不可见后台及权限缺口明确保留。局部实施检查备份、人工修改及网址保护、真实前后结果和回退方法，未改动系统不计为本次通过。

多站信息一致性梳理通过需站点范围、主体关系依据、共用事实适用范围、合理差异及冲突、逐站动作与责任。未确认冲突不可擅自覆盖，未访问页面不能声称检查；已实施站点需匿名回读与相关输出一致，未实施项单列。信息一致性通过不等于 AI 已统一识别、收录或引用。对应任务见 eval 20、21。

## 首版必查行为表

本表是新站从生成到验收的入口，详细行为以链接的专题规范为准。编码前绑定本项目实际页面或功能；验收时在既有清单中记录入口、视口/状态、操作、预期、实际、证据和结论。只看代码、截图或成功提示不能替代对应的交互与数据回读。未启用功能注明依据；默认应有功能不能以缺少企业素材为由省略。

| 范围 | 生成要求来源 | 最小复查动作 |
|---|---|---|
| 资料与业务表达 | workflow.md、content-model.md、design.md | 整包输入已读/未读、版本冲突与素材用途有记录；首页较早说明主体、业务、受众及有依据的特点，桌面手机与原始 HTML 一致；重要能力和数字能追到具体依据 |
| 视觉方向与维护后的布局 | design.md、design-quality.md | 方向不清且包含视觉制作时比较真实资料样稿；成组图片协调且事实保持。隔离项目后台换图、改合法长标题、增减推荐后，在桌面、中间宽度和手机匿名查看受影响布局 |
| 前台列表与阅读 | design-quality.md | 有图、无图、长标题列表及详情实际查看；无重复标题占位图、空列或成片通用口号；返回本栏目可用 |
| 正文层级 | native-php.md | 标题紧邻段落/列表、列表后段落、CRLF 和 HTML 字符；后台打开、改无关字段、保存及匿名回读语义一致，未保存预览一致 |
| FAQ 与前台菜单 | design-quality.md | 分别展开/收起问题；独立页链接不暗示更多重复内容；菜单当前态、链接跳转收起、Escape、视口切换及无脚本入口 |
| 联系与咨询 | inquiries.md | 页面不过度重复说明；手机容易填写；合法提交入库、重复提交防重、失败保留、后台查找及跟进回读；邮箱关闭不影响保存 |
| 后台导航与列表 | native-php.md | 每个分组、刷新、直接编辑和返回；字号、缩进及单组展开正常，叶子点击不展开全部；搜索清除、分页、返回条件有效 |
| 内容编辑与企业设置 | native-php.md | FAQ 直接问答；单页直接编辑且服务端拒绝重复；身份/联系方式优先，首页展示折叠；保存容易找到，无无效字段 |
| 封面与未保存提示 | native-php.md | 当前表单选图/上传/取消、立即预览、保存回读；上传失败和并发失败清理临时文件并保留正文；空文件与未修改不误报 |
| 图片素材 | native-php.md | 上传入口、搜索及清除、分页、紧凑引用状态；隔离图片取消删除、在用保护、确认后实际文件与记录删除，保护外部原材料 |
| 邮箱与账号 | inquiries.md、native-php.md | 常见邮箱自动匹配与手动高级设置；更换端点不复用旧密钥；测试邮件按授权条件执行。账号页显示/隐藏、具体校验、保存后重新登录及初始化不覆盖 |
| 监测与导出 | native-monitor.md | 普通中文概览、技术明细折叠、适用筛选、手机菜单；同条件 CSV 无 HTML 混入，未登录不得读取 |
| 缓存与交接 | native-php.md、handover.md | 内容、模板和解析器更新后原 URL 不错误返回旧页/304；README 的实际入口、默认账号密码与改密入口齐全 |

上述每项分别检查功能正确性与易用性，任一不符合即保留 failed。先修复并复做失败步骤，再检查共用组件影响。新站的页面和功能全量清单仍按下文建立，本表不能替代其他安全、数据、部署和监测要求。

## 每个网站的自查流程

生成网站后按“确定范围 → 建立清单 → 分层检查 → 修复 → 复查 → 判定交付”执行；维护已有网站时按影响范围执行同一流程。代码写完、页面能打开或一个脚本通过都不等于网站验收通过。自查用于发现并关闭已检查范围的问题，不承诺任何环境下绝对没有缺陷。

每个网站均需本节自查。两套企业资料、有无 Skill 对照及独立评审属于 Skill 评测，单独报告，不要求每建一个网站都重新进行整套对照，也不以尚未安排真人评议为由停止可完成的自查。

### 1. 确定阶段与检查条件

记录本次为文件审阅、本地运行、预览部署还是正式上线，以及代码、数据、素材、配置和环境的实际版本。列出已授权的运行、后台写入、备份恢复和监测范围。文件审阅只能给出静态检查结论；缺环境、工具或权限的动态检查保持 not_run 或 blocked，不自行降为可选项。

依据本文件任务表列出本阶段必查项、适用条件与通过依据。用户明确后续再做的监测等模块列为后续阶段；正式上线才可验证的域名、HTTPS、CDN 和线上配置不计作本地已通过。真实访问性能与 AI 引用等后续观察独立记录。

### 2. 建立页面、功能与资源清单

交叉核对 site-plan.md、实际路由、已发布数据、导航/正文/关联链接、sitemap 和公开目录，找出遗漏页、孤立页、空栏目及已删除残留。不能只检查生成器自己导出的目录，导致漏掉的页面也被漏检。

清单覆盖公开页面、每种实际模板、后台模块、查找/新增/编辑/删除及保存前后状态、表单、图片、下载及实际启用的交互。记录每项 URL 或操作入口、预期状态、用途、模板、检查方式及结果；有效分页和业务参数不能被去重掉。仅在授权站点范围内有限速地遍历只读入口，不批量访问退出、删除等会改变状态的地址，不自动提交外部表单。

所有公开 URL 检查状态、正文、元数据及引用资源；每种模板和每个后台模块覆盖实际功能。小型官网逐页查看桌面与手机；页面量大时可按模板及不同内容长度、图像比例、空状态抽样，但必须列出具体样本与未逐页查看的范围。每种模板至少核对 390px、768px、1440px；首屏、Logo、关键海报、主要操作入口和已发现问题不因抽样省略。

分别统计页面、模板、功能和视觉的已检查数/应检查数，以及 passed / failed / not_run / blocked 数量，不把“URL 全通过”写成“全站全部通过”。超出遍历上限、超时或检查中断的范围保留为未检查。

### 3. 按依赖顺序检查

| 层次 | 实际检查与证据 |
|---|---|
| 环境与代码 | 核对 PHP 语法、配置及私有目录、所需扩展、路由和数据库结构；在隔离目标验证空库安装与初始化。启动失败先定位原因，不据此将后续未执行项批量标为功能失败 |
| 页面与资源 | 逐 URL 请求，核对预期状态、正文、链接/锚点及最终跳转目标，检查图片、CSS、JS、字体和下载的真实返回及可加载性。详情地址附加多余路径、后台地址前缀碰撞和不支持的请求方法需返回正确状态；启动脚本需等待首页健康检查成功再报告可访问。错误页不能伪装为 200，资源返回登录页或 HTML 不能算加载成功 |
| 内容与视觉 | 对照确认资料及 theme-plan.md 核对事实、栏目、文案与品牌；实际浏览整页和原图，检查主题完成度、图片裁切、Logo 色差/边框、排版、遮挡、手机重排及内部说明外露。按下文视觉通过条件判断 |
| 交互与访客路径 | 从首页走到业务详情、关联证明/FAQ 和真实联系入口；操作菜单、滚动、切换、键盘焦点、已启用的搜索/筛选/分页及表单的有效/错误输入，核对反馈与数据结果。检查浏览器控制台和网络失败，外部资源故障时核心内容仍可用；截图不代替实际操作 |
| 后台与数据 | 对每个业务内容与素材栏目实际查找、新增、编辑、保存、回读和删除，完成图片替换；企业设置检查保存，概览与监测检查读取和筛选，咨询记录检查实际处理流程。核对权限、持久保存、关联和前后台一致，不能只看成功提示 |
| 安全与恢复 | 按本文件登录与安全、并发事务、备份恢复任务核对。写入测试、失败注入与恢复在隔离库和目录进行；对当前网站代码的检查不冒充专业渗透测试或安全保证 |
| 缓存、SEO 与性能 | 执行下文各项，以原 URL 匿名回读受影响页面、元数据、目录、sitemap 及已启用的 CDN；固定条件测代表页，保留测量原始结果，检查工具总分不能替代细项 |
| 部署与监测 | 本阶段涉及部署时核对实际目标的配置、访问和服务；默认按 native-monitor.md 验证内置采集与报表；选用 GEOInflow 时另核对服务与本站数据。没有监测数据不能靠编造记录补齐，阶段未授权则不执行 |

贯穿功能检查至少走通一次完整链路：后台编辑业务内容并换图 → 保存 → 普通匿名访问原 URL → 核对详情、列表、首页共用位置及关联输出 → 删除 → 确认公开入口和缓存不再泄漏正文。用隔离数据执行，结束后清理本次测试数据并回读最终状态。表单测试采用隔离接收端或已有授权的测试目标，不因自查自动向真实客户发送消息。

### 4. 修复与复查

每个问题记录位置、视口/角色/状态、复现步骤、预期与实际、证据、影响、负责人、修复及复查结果，合并进项目私有验收材料；不把开发检查说明放进官网。安全证据不包含密码、Cookie 或可复用令牌。

发现问题先定位原因，再在既有授权内修复。修复后重做原失败步骤，并检查共享依赖：页头/全站 CSS 变动覆盖使用它的模板及手机；内容字段或发布逻辑变动覆盖关联页、缓存、JSON-LD、目录及 sitemap；权限变动同时检查登录与匿名路径。只看修改过的一张截图或数据库值不能关闭问题。

记录经过复查的最终版本；复查之后的变动须重新判断影响，旧结果不能自动覆盖新代码或新配置。仅对受影响项和关键浏览/保存链路回归，无关且条件未变的有效证据可复用。反复失败时根据新证据缩小原因；缺必要条件且无法继续时记录具体阻塞和恢复条件，继续其余独立检查，不盲目重试或伪造通过。

### 5. 判定能否交付

未授权访问、私有内容泄漏、数据丢失、关键页面/操作失效、发布或删除不一致、虚构业务信息和假入口，以及视觉通过条件中的切字切脸、Logo 异常、遮挡等，均阻断相应阶段的通过，先修复再复查。其余未达到本次要求的项同样保留 failed；细节优化建议与实际缺陷分开，不能把失败项改称建议来绕过验收。

只有本阶段全部适用必查项实际 passed，才报告“本阶段检查通过”。存在 failed、必查 not_run 或 blocked 时，说明未通过或仅完成部分检查，仍可交付文件供审阅，但不称网站已全面验收。每阶段结论不替代整体结论；完整网站验收还需核对所有约定阶段。自查通过不自动触发公开部署或向他人提交。

### 6. 交付检查结论

在项目既有验收材料和交接说明中汇总：检查阶段与版本、环境和时间、各类覆盖数量、实际通过项、尚未解决的问题、未检查/后续观察项及下一步。向用户简要说明“检查了什么、发现和修好了什么、还有什么没有验证”，不以“网站没有任何问题”代替有范围的结论。不要求另建独立的验证文件。

## 完整操作任务

| 检查 | 实际动作与通过依据 |
|---|---|
| 干净安装 | 独立目录和 MySQL 空库，按生成项目的说明配置、建表、初始化管理员；命令与文件存在且能用 |
| 资料与设计判断 | 理解业务、受众、目标和素材，读取相关知识库并搜索、查看官网参考；保留实际来源、比较和选择理由，主题与布局能对应访客需要，不依赖固定行业分类，不根据名称猜业务 |
| 资料与页面 | 按当前企业资料核对来源、缺失、冲突、方案拆页及业务详情网址；文件夹或压缩包有盘点、版本判断、实际阅读范围与图片用途映射，不要求先人工填表，不把未读材料记为已读；原件保留，不执行包内程序。不虚构参数与效果；Skill 评测另使用产品型、服务型各一套资料 |
| 能力与证据 | 从已启用的业务页抽查能力或数字到实际依据的对应：名称、主体、范围、时间和统计口径正确，申请与授权、样本与总量分清；证书图之外有可读事实，私有原件不外露。改动事实后复查共用页面、汇总数字与适用的 JSON-LD，不额外引入复杂后台流程 |
| 共用后端 | 后台改企业信息与产品/服务，首页主视觉、推荐、页头及详情读到同一数据；删除后不残留固定业务事实；刷新及重启后保持 |
| 关联与栏目 | 对每个已启用的内容栏目在后台实际新增，不借助导入或 SQL；维护实际需要的内容关联，核对新建表单、保存、列表及详情，未启用栏目不补建 |
| 后台导航与层级 | 桌面为纵向侧栏，多个相关入口才设二级菜单；侧栏、工作区、分组及当前项有清晰色彩/缩进层次。逐项进入、刷新和直接打开编辑页，检查所属分组展开、高亮、面包屑及标题；无空菜单和错误跳转。手机菜单可展开关闭，不遮挡表单；键盘、Escape、焦点返回及无脚本访问可用 |
| 后台易用性 | 常用菜单、列表、表单和操作符合 native-php.md；无独立来源、公开目录、缓存或命令工具栏目，不将技术项整组搬到默认界面。用普通字段完成新增内容、换图、查看、保存、删除和修改联系方式；无需填写 ID、JSON、确认布尔值或阅读开发说明。搜索/筛选、空状态、错误保留输入及提示均可理解，无全站重复技术横幅；维护人员仍能按说明导出目录和处理失败 |
| 生命周期 | 新增保存即生效；首次有效保存写首发时间，编辑保留；删除后正文、导航、关联、目录及 sitemap 不再公开 |
| 图片与资料 | 上传允许使用的图片，选 Logo/封面，保存后再次修改访客图注与内部备注；核对权限及两类字段不会混出。对照原图查看海报、产品、人物、证书和 Logo 的实际显示，必要文字与主体不被裁切或遮挡；示意图不冒充企业实拍、成果或实力证明，关键条件同时有可读文字。手册或视频有真实文件/链接才检查，无材料明确未执行 |
| Logo 适配 | 区分原图底色/边框与 CSS 附加样式，核对透明度、品牌色、比例和安全距离。检查桌面手机的页头、页脚、菜单及实际启用的吸顶/背景切换状态；无非设计色块、色差、白边或额外边框，原有品牌外框及键盘焦点反馈保留。后台换图后各处显示同步 |
| 内部资料依据 | 不依赖独立后台栏目或手填来源 ID；在私有记录核对事实、素材及关联内容。经企业人员确认本次输入并保存的自有信息可记录企业录入依据，模型生成或教学样例保存不算确认；资质、引用与许可仍核对材料。建站方法/设计参考不作为企业事实依据；缺依据或不许公开时在相应内容处给具体提示，许可撤销处理公开依赖，私有原件和路径不外露 |
| 人工编辑保护 | 先在后台手改，再由 Skill 更新业务条件；保留无关字段和稳定网址，检查关联 FAQ、文章、摘要及 JSON-LD |
| 中断续做 | 发生中断时，核对既有记录与真实文件/数据后继续剩余步骤；确认人工修改、管理员及内容未被重置，已导入记录不重复，结果不明的写入先读回。Skill 评测可在隔离项目保存部分完成状态和人工修改，恢复后检查失败项与受影响链路，不把进度记录当作通过证据 |
| 并发与事务 | 过时表单及导入计划拒绝覆盖；失败无部分写入；数据和文件变更一致 |
| 登录与安全 | 登录、退出、失败限制、超时、会话轮换、CSRF、未授权读写、SQL 参数、输出转义、伪装及超限上传、私有目录不可读取 |
| 抓取条件 | 实际请求正文、robots、sitemap；核对状态、链接、canonical、JSON-LD 与可见事实。记录域名、时间及请求条件 |
| 组件与数据查询 | 核对共用组件来源、版本、许可、依赖和项目集成证据；检查关键查询的索引与重复查询、实际 Web 进程 OPcache 状态，限制另列 |
| 公开缓存 | 检查 MISS/HIT/BYPASS、私有隔离、新增/删除/恢复后受影响页面与目录；覆盖缓存失败及重试，详情见下方任务 |
| 性能与 SEO | 按 deployment.md 固定条件重复测代表页，核对资源、响应、索引规则及结构化事实；保存原始数据，实验室与真实访问分别报告 |
| 预览与发布隔离 | 教学资料内部保持 demo=true，受控预览并禁止索引，审阅人获知样例性质；默认无前台教学横幅。正式发布检查阻止未经核实的样例及假入口，不以隐藏说明代替事实核对 |
| 全站主题 | 对照 theme-plan.md 及已选样稿，检查首页、列表、详情、文章、联系及实际启用模板的配色、字体、图像、布局和组件；方向不清时有按授权制作、实际查看的局部样稿及选择依据，已有方向不强制再做两套。不能仅换 Logo、颜色或只设计首页 |
| 视觉和操作 | 390px 手机、768px 中间宽度与 1440px 桌面，检查主视觉、配色关系、中文排版、连续区块节奏、图片、阅读与重排；操作导航、表单及键盘焦点，保留实际截图与反馈，不只检查横向溢出 |
| 对外内容 | 查看正文、页头页脚、图注、alt、描述及 JSON-LD，教学口径、脱敏/核验过程、裁切理由、开发备注和占位联系方式不混入公开内容；保留真实业务提示、隐私说明及必要署名 |
| 滚动交互 | 对照动效方案操作滚动、悬停、菜单及内容切换，检查初始、中间、结束状态；手机、减少动态效果与脚本失效时正文可读、入口可用，无滚动劫持、遮挡或明显卡顿 |
| 备份恢复 | 独立库和目录恢复数据库、媒体及配置，核对内容、来源、账号、关联及媒体哈希/读回；隔离目标模拟文件写入失败，确认不误报成功、不破坏现有站点 |

正文采用纯文本的项目应转义 HTML；采用受控富文本的项目应检查白名单清理与危险内容阻断，不能把这两种模式混为同一验收。首版只有管理员角色，不验收不存在的多角色审批。

主题验收使用业务、受众和素材条件不同的资料，检查设计理由、全站一致性及实际效果；同类业务应能随品牌和访客需要形成不同表达，跨行业或混合业务也能直接分析。搜索结果、配色表或方案文档不能替代实际页面预览；既有功能测试不自动算作新主题规则验证。

## 日常使用专项检查

- 标准增删改查：每个实际内容栏目使用查找、新增、编辑、删除；新增和编辑共用保存表单，保存后直接生效。默认没有草稿、发布、下架、重新发布按钮或状态筛选。检查服务端也不保留可被旧请求误触发的工作流。
- 按钮：实看蓝色查找、绿色新增、橙色编辑、红色删除，保存蓝色、辅助动作中性；所有主要按钮有背景、文字和明确焦点，不能只检查 class 名。桌面与手机中按钮可见、触达且不遮挡正文。
- 紧凑表单：查看每个已启用内容栏目、企业设置和素材的真实编辑表单；同一面板内常用字段集中、短字段并排、低频项折叠。没有大面积无用留白、一字段一卡片或多屏寻找保存；手机重排后不靠横向滚动操作。
- 实际保存：新增隔离内容后在列表查找，编辑并匿名检查详情、列表、首页推荐、相关内容及目录更新。保留首发时间，修改更新时间；刷新和重启持久有效。
- 删除：实际取消一次，再确认删除。显示对象名称及后果；从列表、详情、导航、推荐、关联和公开目录移除。验证未登录、无效 CSRF、GET、旧版本及重复提交不能误删。内部软删除不意味着公开内容仍可访问。
- 失败保留：空标题/正文、超长输入、无效图片及版本冲突时，保留字段、原始版本与选择；新建错误不创建记录。修正后可保存，不能自动覆盖别人修改。
- 编辑与图片：正文不要求写代码，必要格式控件简单；选择/上传/更换时保留正文、图注和未提交文件。预览若提供，真实显示本次输入，不写数据库；关闭返回输入与焦点。
- 菜单与列表：当前分组和选中项正确，工作台真实计数与最近编辑；查找条件和有效页码贯穿返回。手机抽屉、短屏滚动、关闭、焦点及无脚本降级可用。
- 素材真实删除：登记隔离图片，实际上传、编辑、取消删除、在用引用保护和确认删除；检查数据库行、原文件、全部缩略图和登记的旧文件确实不存在，匿名及管理员旧链接都不可读取，选择器无残留。无回收站或恢复入口；仅界面消失或返回 404 不算删除通过。覆盖 CSRF、旧版本、路径边界和失败提示，桌面与手机均实际操作，不拿真实业务图测试。
- 未保存保护：离开和退出前提醒，取消后会话与输入保留；正常保存不误报。页面内上传和多表单提交不静默丢失另一表单。
- 事实与边界：简单保存不绕过教学隔离、授权素材或明确的事实冲突；私有来源与技术字段不进入访客页面或运营必填项。历史未公开记录保持原可见性。

## 视觉质量的通过条件

按 design.md 的品牌与审美、首屏构图、内容节奏、图像、动态体验、全站一致性及对外完成度逐项检查。按 design-quality.md 将选定参考、已选样稿和实际页面的相近区块并排比较，记录比例、层级、疏密、对比或分组的具体问题、调整动作与同视口复查；缺少参考或样稿时说明本阶段实际依据。不能用“整体高级”或模型自打高分代替判断。

首页与代表性详情先查看、修正，再扩展全站。出现切脸、切字、海报残字、图文重叠、Logo 非设计底板色差或多余边框、内部提示外露、假入口或动效使正文不可读时，直接记录 failed 并修复；不能用 HTTP 200、性能成绩或其余项目通过抵消。卡片堆叠、缺少层次、图片与背景冲突、只有首页完成设计时，按具体问题返回设计阶段。

检查图片必须对照原图和桌面/手机显示，并查看同组图片的明暗、背景与主体尺度是否协调；不得用改变产品颜色、结构、证书内容或全局滤镜取得表面一致。检查动效必须实际操作，记录滚动前中后或短视频；静态截图不证明交互正常。无法运行或缺少视觉工具时保留 not_run，不声称效果已验收。

在隔离项目按 design-quality.md 的内容变化任务，通过后台保存合法长标题、不同图片比例、无封面及零/单条/超出推荐上限的内容状态，匿名回读并查看受影响模板的 390、768、1440px 表现。按实际功能选择样本，检查裁切、断行、空状态、推荐上限、列表入口与手机重排；保存成功不能代替布局通过。恢复临时数据后回读最终页面，日常更新按实际影响复查，不重复无关且条件未变的检查。

Skill 评测由至少两位未参与制作的评审人分别评议品牌辨识、信息疏密、图文质量、全站一致和操作体验，与实际参考并排比较。记录各自的可接受/需修正、页面区块、视口及理由，修正后同视口复查。普通客户项目按约定的审阅人和节点执行；Agent 检查与真人评议分开，不伪造独立认可，人员未参与时该项保持未执行。仅修改 Skill 时只更新规则和任务定义，不生成网站或代跑这些任务。

## 缓存、发布与失败处理

在隔离项目准备允许使用的产品或服务、关联 FAQ/文章及图片，记录当前数据和缓存配置。每项保留请求条件、URL、响应头、状态、正文关键值及时间；不把 Cookie、令牌和凭据写进报告。

1. **命中与隔离。** 同一匿名 URL 首次为 MISS，随后为 HIT，实际后台、登录、预览、带身份状态和私有媒体为 BYPASS/不公开。先匿名后登录、先登录后匿名分别请求，公共缓存不含私有信息；改变合法分页不能串页，未知参数不突破权限。
2. **内容更新。** 先预热详情、列表、首页推荐、关联 FAQ/文章、目录及 sitemap；从后台修改已公开条件与图片说明，再以原 URL 匿名请求，核对所有受影响输出和 JSON-LD。检查首发时间保留、更新时间真实、条件请求不会对旧内容错误返回 304。
3. **新增与删除。** 未保存输入不进入公开页面；新增保存后可发现，删除后源站正文和各入口、关联、目录及 sitemap 不再公开。已启用 CDN 时分别回读源站与边缘，记录清理完成时间和延迟；未启用则记录该条件不适用。
4. **替换与恢复。** 后台替换 Logo/封面后检查共用位置、实际资源版本及普通浏览器缓存；在隔离目标恢复数据库/媒体后清理旧缓存，回读恢复内容，不能显示恢复前的数据。
5. **失败与并发。** 在隔离环境注入可控的缓存写入/清理失败，必要时模拟已配置 CDN 的失败响应。确认数据状态准确，后台用“内容已保存，部分页面暂未更新”等普通中文说明受影响页面与下一步，技术详情在私有维护记录可查，失败任务可安全重试；恢复权限后重试不重复插入内容。检查旧请求与发布并发时不会把旧 HTML 放回当前缓存，删除不因动态回退而泄漏正文。

故障注入不针对现网、全局权限或其他项目。源站正常但 CDN 仍提供删除正文时此项失败，不能以数据库状态、强制刷新或添加随机参数后的成功覆盖。缓存问题修复后重复对应普通访问及私有隔离检查。

## SEO / GEO 与性能检查

SEO/GEO 共用技术按实际页面类型检查，并执行以下反例：

- 直接获取原始 HTML，关闭脚本仍能读业务条件、FAQ 与链接；点击关键路径可达，没有空栏目或假入口。
- 核对各页独立 title、description、可信绝对 canonical、内链和公开目录，JSON-LD 可解析且与可见事实一致；检查企业名称、产品条件及日期更改后的同步。
- 请求不存在地址、未公开、已删除地址、后台和私有目录，确认相应状态及访问限制，无泄漏或软 404；有网址迁移时实测 301/308 目标、无循环并已更新内链。
- 核对 robots、页面 robots 与 X-Robots-Tag 的组合；预览不能公开索引，正式公开页不能遗留 noindex、错误域名或全站抓取禁令。sitemap 仅含有效规范页，lastmod 有事实依据。
- 自动检查工具只覆盖其实际能力；标题存在或 JSON-LD 语法正确，不代表内容质量、索引、富结果或 AI 引用达标。

Schema 另核对页面实际输出、类型与字段适用性、稳定 @id 与内部引用、企业和服务/产品的关系、sameAs 归属及公开范围。Schema 词汇校验与平台富结果检查分开；无对应富结果类型不等于结构化无效，FAQ 标记不作为 Google FAQ 展示达标项。修改一项真实业务条件后，检查正文、JSON-LD、相关页和缓存同时更新；不能只验证静态示例文件。

GEO 内容验收从目标问题选取对应页面，核对能否独立读出主体、回答、适用条件、依据和行动入口；参数、案例和原创信息必须可回到确认资料。检查同义问题是否造成重复薄页、不同门店/版本是否混用，以及公开证据与内部来源是否正确分开。

交接记录保留目标问题/意图、页面、实际发布时间和观察安排。未约定平台测评时只验收此安排及已实现网站，不要求先获得 AI 引用才能交付。已约定时按 deployment.md 的观察规则保留完整平台证据，分别报告提及、事实准确、官网引用、引荐访问及业务事件；缺少可比基线不计算提升率。可选站长工具或 IndexNow 分别核对已接入、已提交和实际平台结果，不把通知回执当索引证明。

性能按 deployment.md 的协议执行：首页、产品/服务、FAQ、文章代表页，桌面和手机固定条件，各选定场景至少 3 次。保留冷热浏览器缓存、源站/边缘缓存层、LCP、CLS、TTFB、资源体积、请求数和原始报告；主要交互单独操作并记录，TBT 与 INP 不混用。缺页面类型、工具或数据时说明未测范围。

通过判断分开记录：实验室测得的 LCP/CLS 是否达到目标、主要交互在本次测量下的表现，以及真实访问三项指标的第 75 百分位是否达标。只有实验室证据时，真实访问状态保持 not_run 或待观察；低资源体积、HTTP 200 或 Lighthouse 总分不能替代这些判断。性能修正后按同条件复测，并回看图像与动效质量。

## 内置监测验收

执行 native-monitor.md 的自动检查与浏览器清单，必须验证匿名请求 → 实际状态入库 → 登录后台回读、前端 token → 事件入库 → 去重和归因显示、严格 GET 200 覆盖与当前目录一致。逐项核对主流平台清单与可识别范围。官方清单、未匹配 UA、未知身份、过期、无效资料与历史缺证据分别验证；普通搜索、robots 控制标记、厂商网段和引荐浏览不能混入 AI 已核验请求。训练、搜索、用户触发和浏览器代理分列，并核对规则版本留存；缺能力与零记录分开显示。导出、筛选、分页、手机横向表格和菜单实际操作。

验证未登录不能读取报表/CSV；管理会话、DNT/GPC 与识别机器人不进入访客事件；伪造转发头不能提升来源核验；事件签名、同源、大小、限流和重复提交有效。校验日志导入重复不增、错误整批回滚、清理与预览/正式来源隔离。测试结果与真实 AI 到访分开。测试前登记隔离库、来源或请求/事件 ID；仅回滚或删除可准确识别且获准清理的测试对象，不清空业务表、监测表或限流表。正式范围用独立实例验证；无法安全清理时保留并说明影响，不冒充真实效果或已清理。清理后保留验收回执。

## 可选 GEOInflow 与修复复查

以下仅适用于明确选用原版 GEOInflow 的项目。


新部署先核对来源记录：官方仓库或完整提交归档、选定与实际 commit、工作树差异、依赖锁文件、部署脚本及许可。原项目代码直接使用；源码包、已构建镜像、服务运行和数据接入分开验收。归档本地哈希不能冒充官方签名验证，已有源码及用户改动不得被覆盖。

按 geoinflow.md 先验证适用部署路径：已有实例核对健康、权限及配置保留，不自动升级；没有实例且已授权新部署时，实际检查环境、固定版本并安装。验证应用、两个 worker、数据库与缓存服务健康，完成首次登录、修改默认密码及分析时区配置，记录端口、持久卷和实际访问地址。只写文件或首页可打开不能算部署通过。

在隔离部署环境检查提交不匹配、目标目录已有内容、端口/资源不足、已有数据但配置缺失等情况，不能覆盖原配置、删除数据或错误报告成功。首次安装与复用分别留证；同版本重复执行验证配置、账号、站点和数据保留，应用和 worker 使用同一目标构建，仅在该操作已获授权且可隔离时执行。备份与恢复需在独立库验证；官网 MySQL 与监测 PostgreSQL 分别记录。

1. 在健康实例中建立或选中授权站点，核对域名、归属、实际站点标识及重复创建情况；从官网后台打开本站入口，核对登录及站点隔离。浏览器采集按需检查，页面短编号不能替代采集 UUID。
2. 对照安装版本核对实际导出格式，再原生导入当前公开目录与获准日志。目录须能直接被接收端解析，核对有效/拒绝条目、数量、路径和范围；日志分别核对接收、排队、处理完成及原始记录，处理失败不能标成接入通过。自有包装对象或网页 HTTP 200 不代表导入成功。标明真实或教学来源、时区、区间、身份依据及缺口，不直接改监测数据库伪造结果。
3. 在原生界面回答谁访问、哪些页面访问、下一步处理哪页。核对 GET 2xx 或精确 GET 200 的实际口径；重点页逐项核对并列分母。
4. 覆盖成功、403/429、404、5xx、未见记录、仅 UA 声明、未知用途、未接入和日志不完整状态。不能将未接入与缺数据填成零。
5. 对一条有依据的异常定位原因，在授权范围修复，回读页面，再在 GEOInflow 核对后续日志。没有新访问时标记待观察，不能仅凭浏览器成功就称爬虫恢复。
6. 删除页面后核对网站目录和远端目录；仅 upsert 导入不能证明历史条目已删除。记录实际处理或明确排除范围。
7. 教学日志只能证明该演示流程的行为。真实访问另需真实日志；收录和 AI 引用另保留平台证据。

启用 CDN 时核对日志来自源站、边缘还是二者，明确缓存命中是否被采集、重复请求如何识别及观察区间是否完整。缺少边缘日志时，源站无记录不能证明无人访问，覆盖率的范围和限制必须保留。

此可选模式不要求复制原版图表。部署条件不足、实例不可用、权限缺失和日志未接入分别记录；已具备部署条件时按授权新建实例。服务已部署但缺日志不算数据接入通过，不用伪造数字补齐验收。

## 评测资料与对照

测试资料由具体项目按授权提供，记录 project_input_dir、素材目录与业务变更说明；不依赖 Skill 内置的虚构企业数据。evals/evals.json 定义可复用任务，执行前将所需输入映射为实际路径。覆盖完整、缺失、冲突和更新场景时，应在隔离副本中准备输入，不能篡改真实资料；未执行的任务保持 not_run。

两套新建资料均要走“建站 → 后台改业务内容 → 各已启用内容栏目保存与回读 → 前台与视觉检查 → 缓存、SEO 与性能验证 → 查看内置访问监测 → 局部更新 → 匿名回读”。各套资料按业务需要选择栏目，不要求两站启用完全相同的内容类型。旧站与多站另按场景交付验收，不强制套用新站流程。缺失及冲突任务允许推进确认部分，同时阻止无依据内容公开；监测条件未具备时该段保持未执行，不因此省略其他有条件完成的步骤。

Skill 评测安排有无 Skill 对照，执行按授权推进。两组采用相同 Agent、模型、工具权限、输入、品牌要求、环境与交付要求，保留实际提示词、输出及所有补充指导。分别用独立会话、项目和数据库，对照组不读取 Skill 文件或实验组输出。记录用时、事实与模块遗漏、主题适配、错误、求助次数、修复次数及人工代操作。性能对照固定主机、网络、素材和测量条件；资料整理比较不能代表全流程比较。未完成两套资料或部分任务时只报告已比较范围，不预设 Skill 优胜。

独立试用由未参与制作的人仅按说明完成；制作人代操作要记录。部署或权限未准备时不能将任务算作成功，也不直接归因为 Skill 能力不足。

## 顾问价值对照

比较的是同一执行环境中的有无 Skill，不将 Workbuddy 或其他工具名称视为能力差异。双方收到相同业务问题、原始资料、品牌约束、工具权限、环境及交付要求，对照组不接收本 Skill 的规则正文和实验组产物；保留其正常指导及人工帮助，不故意设置弱提示以证明优势。

分别记录新建官网、旧站诊断与局部改造、多站信息一致性梳理的完成范围、达到同一标准所需时间、事实与模块遗漏、错误、额外提示、返工和独立接手结果。未达交付标准的快速生成不能算有效提速。缺少资料、实际操作或独立试用时报告可比较范围和限制；不从一个首页、一套资料或局部结果推出普遍优胜，也不宣称通用 AI 无法完成。

## 工具边界

scripts/audit_site.py 仅辅助检查同站公开目录页：直接返回 200 HTML、有标题、一个 H1，以及正文文本基础条件；排除导航、页眉页脚、脚本等文字，优先使用 main/article 区域。记录最终网址、跳转和失败原因，目录中的跳转页需核对并改为有效规范地址。文本长度只用于发现明显空页，隐藏样式、业务完整性、事实、视觉、后台、安全、缓存、性能和平台引用仍需分别检查。canonical 与 JSON-LD 只作存在性记录，不代表内容或语法已核验。输入为含 url 的顶层目录数组，可使用宿主公开目录或监测 CLI 的基础目录导出。

授权执行时使用实际文件路径：

~~~text
python scripts/audit_site.py --catalog <公开目录JSON路径> --base-url <本站HTTP或HTTPS根地址> --output <私有检查结果路径>
~~~

抓取条件正常不证明已抓取、收录、引用或产生业务效果。

## 全后台易用性检查

逐页检查工作台、每个内容栏目、素材、咨询、企业设置、邮箱、账号和监测分区。按日常任务查找多余字段、重复入口、技术说明和跨页操作，优先直接输入、合理默认值、就近帮助和低频折叠，不以删掉校验或重要状态换取简洁。

浏览器验证 FAQ 输入与预览保存、单页直接编辑、封面原地选择/上传与回读、企业设置折叠及保存、图片状态与搜索、咨询跟进和通知展开、菜单当前态及手机分组切换。文件为空、选择后取消、未修改和真正修改分别检查离开提示。补充验证同一天连续编辑两条内容后的最近编辑排序；取消勾选及清空关联后制造校验错误，确认本次空值保留，不恢复旧勾选。补充验证上传校验、并发失败的文件清理、引用保护和纯净导出；生成的测试内容与文件完成后清理。真实邮箱发送及其他未测外部能力单独记录。

## 全前台易用性检查

逐页查看首页、所有已启用栏目列表、代表详情、FAQ、企业介绍与联系页。实际浏览器检查桌面、768px 和 390px 的首屏、正文及页尾；验证有图/无图、长标题、空字段、问答展开、菜单开关与跳转、返回列表、联系表单必填提示。排查重复标题、假封面、空列、重复口号和咨询前的多余步骤，不能只以 HTTP 成功或无横向溢出代替视觉验收。

正文回归覆盖标题与正文相邻、标题与列表相邻、列表与普通段落相邻、换行及 HTML 字符转义，并比较后台编辑、预览、保存和前台结果。模板或正文解析逻辑变化后验证缓存失效，避免浏览器继续显示旧版。图片核对区分加载失败和视口外尚未加载的懒加载图片，滚动到对应位置后再判断缺图。检查生成的同站链接、图片、控制台错误和表单状态；验收记录只写实际执行的范围。
