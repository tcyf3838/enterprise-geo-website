# 企业 GEO 官网 Skill

面向 **GEO 顾问**，帮助不熟悉网站开发的顾问，将企业资料整理成可信、可维护的官网，建立 SEO／GEO 基础。支持新建官网、旧站诊断与局部改造、多站信息一致性梳理。新站采用 **H5 + 原生 PHP + MySQL**，包含前台、管理后台、数据库和内置访问监测。

Skill 把资料判断、页面规划、设计、开发和验收组织成可重复的流程，帮助减少遗漏与返工。包内提供执行规则、监测代码和辅助工具，具体企业网站由 AI 按项目生成并验证；企业人员通过中文后台维护内容，中断后可依据项目记录继续工作。

## 适用场景与交付

| 场景 | 解决什么问题 | 推荐交付 |
|---|---|---|
| **新建官网** | 从杂乱资料中确定有效内容、页面和功能，搭建可维护的网站 | 内容与页面方案、全站设计、独立前后台及数据库、SEO／GEO 输出与监测、安装维护说明、实际验收记录；包含上线时另交正式环境与维护交接 |
| **旧站诊断与局部改造** | 找出内容、体验、维护和抓取问题，确定修改顺序 | 页面证据、问题与优先级、逐页改造方案；同技术栈且具备源码、数据和权限，经兼容性核对后交约定修改、备份回退与复查结果 |
| **多站信息一致性梳理** | 理清多个网站的主体、共用事实与合理差异 | 站点关系、共用事实、差异与冲突、逐站修改建议；包含实施时，按旧站流程逐站交付改动与复查 |

按约定阶段交付方案、代码、本地运行或上线结果。商城、复杂审批、任意旧站自动迁移、多站集中管理及持续代运营需另定范围。详见[完整交付说明](references/handover.md)。

## 快速开始

### 快速安装（WorkBuddy / Codex）

打开 WorkBuddy 或 Codex，复制下面这段话发给它：

```text
请帮我安装这个企业 GEO 官网 Skill：https://github.com/tcyf3838/enterprise-geo-website
请按当前工具支持的方式安装完整的 enterprise-geo-website，并检查能否在新对话中调用。如果有一步需要我手动操作，请告诉我怎么做。
```

安装完成后，准备好企业介绍、产品服务和品牌素材，即可参考对应工具的调用示例开始使用。

### WorkBuddy

**调用示例**：新建任务，在对话中发送以下内容，替换括号并提供可读取的资料位置：

```text
使用 enterprise-geo-website，为【企业名称】建设官网。
资料位置：【文件夹、知识库或网址】。
目标客户是【客户类型】，希望访客【咨询、选型、预约或下载】。
本次先整理内容、页面和全站主题方案，确认后再生成前后台并做本地检查。
请列出资料缺口、交付内容和验收办法。
```

### Codex

**调用示例**：在对话中用 `$enterprise-geo-website` 指定技能，再说明任务：

```text
$enterprise-geo-website
请为【企业名称】建设官网，资料位置：【文件夹、知识库或网址】。
目标客户是【客户类型】，希望访客【咨询、选型、预约或下载】。
本次先整理内容、页面和全站主题方案，确认后再生成前后台并做本地检查。
请列出资料缺口、交付内容和验收办法。
```

**首次得到什么**：按两个示例中“先做方案”的指令，首先得到可用资料与缺口清单、栏目和页面内容规划、全站主题方向，以及建议交付和验收办法。重点确认业务信息是否准确、页面是否覆盖重点、视觉方向是否合适；确认后再要求在独立项目目录生成网站并检查。账号与密钥在实际接入时单独提供。

旧站可说明“先诊断【网址】的内容、体验和抓取问题，交改造建议”；多站可说明“核对这些网站的主体与业务信息，交共用事实和逐站修改建议”。

## 生成与复查

生成前将[首版必查行为表](references/acceptance.md)绑定到项目的页面与功能清单。先实际检查代表页面和后台表单，再扩展全站；交付前分别验证功能正确性与易用性，覆盖桌面、平板和手机，以及保存回读、菜单、问答、联系表单、图片和邮箱设置。视觉检查包含换图、长标题和内容增减后的布局，并对照选定参考修正具体问题。每项有实际证据，未检查不算通过，不能仅凭页面打开或脚本通过宣布完成。

## 生成网站后的后台登录

- 默认账号：`admin`
- 默认密码：`123456`
- 后台地址：以生成项目交付的管理后台地址为准。
- 修改密码：登录后台，进入 **网站设置 → 账号设置**，填写当前密码、新密码和确认密码后保存。

默认账号密码仅用于新站首次初始化；重新启动或维护已有网站不会覆盖已修改的密码。这是网站管理后台的凭据，不是 MySQL 数据库或邮箱 SMTP 的账号密码。

## 推荐输入

可直接提供企业资料文件夹或压缩包，也可提供单份文档、图片、视频、网址或知识库。AI 先盘点文件、核对版本、查看素材并对应到页面，再询问影响当前工作的缺口；无需先整理成固定表格。

| 资料 | 建议内容 |
|---|---|
| **企业与目标** | 企业／品牌介绍、主体关系、业务地区、目标客户、客户问题、希望访客完成的行动，以及本次范围、期限和验收负责人 |
| **产品与服务** | 分类、用途、参数、适用条件、流程、周期、交付与售后；价格按实际公开范围提供 |
| **内容与依据** | 案例、资质、检测或实测资料、文章、常见问答、下载文件；宣传某项能力或数字时，提供相应明细或证明，如专利名称与编号、证书主体及有效期、案例结果及统计口径；注明版本、来源与公开范围 |
| **品牌与素材** | Logo、品牌规范、获准使用的图片与视频、参考官网及喜欢或需要避免的风格 |
| **联系与维护** | 真实电话、邮箱、地址、二维码；表单接收人和渠道、常更新的栏目及后台维护需求 |
| **站点与现有数据** | 已有域名、主机、预算和维护条件；可复用的关键词、目标 AI 问题、诊断、搜索报表与访问记录，注明时间和范围 |

**旧站**另给网址、问题和必须保留的内容，实施时补源码、数据、备份与权限。**多站**另给站点清单、各站主体、业务地区、负责人和允许保留的差异。部署资料可在准备上线时补齐。

缺失资料先列清单，继续推进有依据的部分；教学样例用于受控预览，正式公开前核实事实、素材许可和联系入口。完整的十类资料与场景补充项见[推荐输入详表](references/workflow.md#推荐输入)。

## 主要功能

| 模块 | 做什么、怎么做 |
|---|---|
| **全站设计** | 根据业务、品牌素材、知识库和官网参考确定配色、排版、布局与交互；方向不清时，在约定制作阶段用真实资料比较局部视觉样稿；统一同组图片的呈现，查看首页和代表详情的桌面／手机效果后再展开全站 |
| **管理后台** | 纵向菜单、必要二级栏目和中文表单；企业人员可维护内容、图片和联系方式；前后台共用 PHP 逻辑与 MySQL，保存后同步受影响的页面、结构化数据及缓存 |
| **SEO／GEO 共用基础** | PHP 输出完整正文，建立有效内链、规范网址、站点地图和抓取配置；企业、产品／服务、文章等模块按实际类型生成 Schema JSON-LD，与正文共用数据并随内容更新 |
| **SEO** | 将搜索需求分配到页面，完善标题摘要、主标题与图片说明；具备账号权限时用站长工具检查索引、查询、展示和点击，处理重复页与访问问题 |
| **GEO** | 首页及重要页面尽早讲清企业业务、服务对象和有依据的特点；将客户问题对应到页面，写清答案、条件、参数及可核对的证据，连接案例与业务入口；后续用真实 AI 回答检查描述准确性和官网引用 |
| **访问监测** | 接入网站请求和浏览脚本，提供浏览／已核验 AI 请求／AI 引荐／联系下载点击指标、每日浏览柱状图、AI 分类明细、逐页抓取覆盖进度、异常汇总和请求导出 |

监测维护主流国内外 AI 平台清单，训练、搜索、用户触发和浏览器代理分列；**身份声明、来源已核验、暂无法确认分别呈现**。浏览、抓取与点击各自统计，不能据此认定已被 AI 引用或产生咨询。数据范围、平台名单和维护方法见[监测规范](references/native-monitor.md)；需要独立系统时可选[原版 GEOInflow 接入](references/geoinflow.md)。

## 使用条件与验收

- **执行工具**：支持读取完整 Skill 与企业资料、创建和修改文件；检索、命令执行、浏览器查看和部署权限按任务阶段提供。
- **推荐环境**：支持原生 PHP、MySQL、HTTPS、备份和定时任务的主机，选择仍受维护且兼容的稳定版本。扩展、辅助工具和资源费用按[部署规范](references/deployment.md)及[监测安装说明](references/native-monitor.md#文件与安装)核对。
- **完成依据**：逐项检查内容、桌面／手机效果、交互、后台保存与匿名回读、数据、安全、缓存、SEO／GEO 输出和监测，修复后复查。代码生成、本地运行、正式上线分别记录，未检查项说明原因与下一步。

辅助脚本只验证各自范围，完整网站按[自查流程](references/acceptance.md)验收。搜索收录、AI 引用与实际咨询另用平台和业务记录观察；包内评测任务定义不代表已通过实测。
